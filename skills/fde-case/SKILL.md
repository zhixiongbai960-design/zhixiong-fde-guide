# 案例教学设计

读取真实案例材料、对应教学日、班级基础、已有方法和课时。没有真实案例时给待填框架并问讲师提供一个具体任务，不替他编故事冒充经验。第四天侧重确定性逻辑/API，第五天知识与数据，第六天三层协同；实际主题变化需标共创建议，不擅自改变主线。

每个案例只指定一个主要新增复杂度；列真实项目与课堂简化差异，保留关键约束。输出轻量案例卡：场景/用户/问题、已有证据、一天内核心结果与排除项、理论增量、最小架构、材料/接口/授权、正常和相关异常样例、人工责任、可复用配置/Skill、验收与复盘。具体行业规则来自讲师和材料，未知不补造。

按“需求 → 评审切小 → 方案 → 构建 → 按需接入 → 测试交接 → 复盘”安排教学。预留测试/交接/复盘保护时段，不能靠加夜课达到计划。课时未定给分配建议和待确认，不宣称已可容纳。

设计一项未直接演示的新输入、规则变化或异常，放入原测试时段，不另加项目；让学员先说改哪里，再运行核对，记录提示与成品使用，不能用复制成功当独立迁移。不要把参考答案提前给学员后仍称未知变化。

要求非原开发者用实际教学资料限时预演，记录配置/讲解/练习/测试/交接耗时、阻塞和帮助。没有实际预演结果就标“待预演”，不能凭文字计划判准入通过。超时先缩小范围/提供骨架，仍保留本人规则修改与核验，不删测试。

输出案例卡、预演计划或真实记录、独立变化任务、共创待决项。主讲者负责材料修订，预演者反馈，主理人与相关讲师确认范围；未知人名和分工标待定。发布教学材料需核对隐私、授权和许可；不自动公开客户资料。

预演结论仅覆盖实际预演者、工具、任务和条件，不由一次单人预演外推全班容量。班级人数、基础差异和助教响应负荷须另作组织核对；支持阈值与通过标准由教学团队根据现场资源确认，未有依据不虚构统一人数比或准入分数。
