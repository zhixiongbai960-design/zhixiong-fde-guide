# FDE 课程覆盖与输入输出衔接

志亚科技出品 · 作者：白志雄 · 版本 0.5.0

0.5.0 是当前参谋版本，公开发布以对应仓库提交为准。方法负责具体分析、产品/架构/接口/权限设计、工程交接与证据评审，不直接或委派承担业务实现，不代最终决定。课程仍可包含编码与运行，由学员、讲师及专门编程工具完成，不能把课程产出都算成本技能实现。18 独立包已按精确受测字节同步；旧总包和8旧入口保留旧职责，不代表本版。模块验证、专家回归、发布与宿主安装须分别核对。

本表保留**本次七天 3+3+1 共创方案的示例映射**：前三天建立个人 MVP 的基础方法，第 4–6 天以讲师真实案例反复完成闭环并各引入一个主要复杂度，第 7 天做验收、展示与复盘。小节号沿用该方案的七天 56 个小章节，便于对照原课纲；不是所有训练营的统一排课，也不表示 Datawhale 或其他合作方已认可或定稿。

三天营和其他形式以实际课表、学员基础与课时为准。没有课表时先给不绑定日期的案例框架，不把七天内容强塞进三天。下面的课内映射与总技能的全项目能力分开列示。

## 安装与方法入口

完整帮助的目标入口是[专家技能 zhixiong-fde-Expert](zhixiong-fde-expert/SKILL.md)。总包内置全部方法；18 个独立模块也可分别使用，每包带齐所需方法和资料，不要求互装依赖。它们由[同一份源码](../skill-source/src/methods/)生成，对应关系见[注册表](../skill-source/src/registry.json)，总包更新按发布版本进行，不自动跟随单模块变化。

需求入口统一以 [zhxbai-fde-need](zhxbai-fde-need/SKILL.md) 说明。原 `requirement-analysis` 继续兼容已有使用习惯；其需求追问、课堂评审回写和确认后生成 MVP 规格能力已纳入新模块及总包，学员无需另装旧技能。

## 示例映射一 课前与前三天基础方法

前三天围绕学员自己的一个小任务建立方法。表中模块表示可以调用的能力，不要求每节单独安装，也不要求把已经清楚的输入重新问一遍。原八个课程模块是教学主题，18 个独立模块是工具入口，两者数量不必相等。

| 示例课程环节 | 主要模块 | 方法重点 | 本环节可检查的产出 |
|---|---|---|---|
| 课前准备 | ready | 打开材料、运行示例、找到输出、改输入重跑 | 本人/协助/未执行及证据，阻塞和支持安排；不作编程考试 |
| 第 1 天 1.1–1.3 | knowledge | 从经历与材料形成最小知识资产，核对来源和适用条件 | 一个任务的材料索引、带出处回答、冲突和缺口 |
| 1.4–1.5 | scope；按需 client | 比较候选和投入条件，理解 FDE 的责任边界 | 候选理由、已知/未知、可验证小范围；不延展为完整经营课 |
| 1.6 | need | 真实任务走查、As-is/To-be、目标/问题/卡点/依据 | 一页需求、本人核对状态和评审疑点 |
| 1.7 | review，need 接评审回写 | 六组需求检查，只补关键缺口，区分事实与评审建议 | 指定下一阶段的结论、依据、缺口与修订需求 |
| 1.8 | scope + need | 本人确认范围后按请求生成规格，区分包含/排除/人工保留 | MVP 需求规格、确认状态、开工阻塞 |
| 第 2 天 2.1–2.4 | design；按需 doc | 完整任务流程、最小组件、字段规则、正常异常设计 | 原规格上的设计补充；需要复核时给具体设计评审意见 |
| 2.5–2.7 | build，design/knowledge 支持 | Agent 职责、方法/配置分离、必要上下文、按需工具 | 本技能给方法规格、配置项、样例预期与工程交接；学员用专门工具实现并修改一条规则 |
| 2.8 | build + deliver；需工程交接或代码证据评审时 code | 首跑、原始证据和分层排错 | 实际首跑记录或未运行/受阻；不以生成源码代替运行 |
| 第 3 天 3.1–3.4 | deliver；按需 code/run | 来源字段核对、异常停止接管、换输入回归、重启恢复配置 | 正常和相关异常的版本化记录、修正与回归结果 |
| 3.5–3.6 | deliver | 按需求验收、同伴根据说明试用、最小交接 | 已验证范围、未测项、同伴试用状态、运行说明 |
| 3.7–3.8 | deliver；run 支持复用检查 | 短演示、证据叙事、复盘回写和下轮验证 | 实际结果与限制、可迁移方法、下一次验证 |

这里的顺序是该课表的教学安排。实际项目可以从已有需求、设计或错误直接进入对应环节；不会因为调用某个模块而强迫回到第一节。

## 示例映射二 第四至六天案例循环

这三天使用讲师提供的真实案例，不预造讲师经历。每例先明确真实项目与课堂简化差异，保护测试、交接和复盘时间，再安排一项未直接演示的新输入、规则变化或异常。前三天学过的方法继续使用，不每天重新讲一套需求问卷。

| 示例课程环节 | 本日主要增量 | 复用模块与循环 | 产出及迁移检查 |
|---|---|---|---|
| 第 4 天 4.1–4.8 | 确定性逻辑/API；只接任务确有必要的能力 | case 准备；need/review/scope 收敛；design/build，按需 code/team；deliver 验证 | 一条最小真实链路、连接与权限事实、正常/相关异常记录；能解释新增能力为何必要 |
| 第 5 天 5.1–5.8 | 知识依据、业务状态及更新维护 | knowledge/design/build；按需 team/code/run；review/scope 仅复查受影响内容；deliver 交接 | 来源与版本、状态读写边界、更新责任及新样本检查；不把检索命中当正确性证明 |
| 第 6 天 6.1–6.8 | 三层责任协同、跨层排错与异常恢复 | design/build；按需 code/team/run；deliver 贯通；next 处理依赖和窗口 | 完整任务与分工、跨层故障证据、复跑和接管说明；三层是责任分工，不强制建三套系统 |
| 每个案例的共创与预演 | 限时可教性与独立变化 | case，相关专业模块按需要参与 | 案例卡、非作者预演实际记录、独立变化任务和未决项；未预演不能写准入通过 |

共同循环：**需求与证据 → 评审切小 → 方案 → 构建 → 按需接入 → 测试交接 → 复盘迁移**。各环节复用前三天产物形式，只补本例新增的规则、材料、依赖和验证；学员说明本次独立改变了什么、得到哪些帮助，再核对实际结果。主讲者自己跑通，不等于全班能够按时完成。

## 示例映射三 第七天验收与复盘

| 示例课程环节 | 主要模块 | 方法重点 | 可检查产出 |
|---|---|---|---|
| 第 7 天 7.1–7.8 | deliver；run/next 按需支持 | 验收、交付包、证据叙事与问答、评审回写、迁移、下一轮验证 | 注明版本和条件的验收证据、最小运行与交接说明、实际结果/限制、修改记录和下一步 |

路演讲谁遇到什么问题、为何选这套方案、实际结果是什么、还缺什么验证。没有测量不编造收益，没有同伴试用不代称通过；早期需求初评仍讲场景、卡点和目的，不套最终产品路演模板。

## 换成三天营或其他课表时

1. **先确认实际课表**：目标、可用课时、学员已有能力、主工具和可用材料。七天示例的小节号不迁作默认安排。
2. **保留一个完整小闭环**：明确需求与范围、最小设计/构建、正常和相关异常核验、交接与复盘。已有能力直接复用；复杂度超时就缩范围或由讲师/开发工具提供工程骨架，不删掉测试来凑完成。
3. **案例按条件选**：每例只指定一个主要新增复杂度；是否需要外部接口、存储或应用代码取决于任务，不取决于某一天的标题。
4. **先预演再决定容量**：非原作者按实际资料限时操作，分别记录配置、讲解、练习、测试、交接和帮助。班级人数、基础差异和助教负荷另行核对，不用一次单人成功推定全班可行。

## 模块之间的输入输出交接

每次交接只带足够材料：项目/需求和范围版本、已有正文、确认来源与状态、证据出处、未知与冲突、权限/责任、上一环节实际状态。沿用同一份需求和项目记录，更新受影响内容，不为每个模块重复写一套报告。

| 交接 | 输入 | 输出与保留状态 |
|---|---|---|
| knowledge → need/review | 必要材料、来源/版本、经历与冲突 | 可回查的依据；材料未知仍未知 |
| need → review/scope | 需求描述、本人核对状态、评审意见 | 阶段判断与范围建议；建议不自动成为确认 |
| review/scope → need | 已认可的问题、本人确认范围、剩余未知、规格请求 | MVP 需求规格；与需求描述用途不同，不重复造平行版本 |
| need → design/doc | 现有规格、可分享样例、确认范围与约束 | design 补实现分工和测试；doc 评现有设计并给具体修订，两者不重做访谈 |
| design/doc → build/code | 已确认方案、规则、输入输出、依赖与实现授权 | build 给业务 Skill 方法规格与验收；code 给应用/接口设计和工程交接，用户另选执行者实现；源码、单测、实接分别记录 |
| build/code → deliver/run | 版本、配置位置、实际测试结果、原始失败与限制 | deliver 做本轮验收交接；run 验证日常使用与客户接管，不继承未经测试的稳定性结论 |
| deliver/run → knowledge/build/next | 实际反馈、已验证方法、适用条件、未测和新依赖 | 本技能按请求更新分析/设计记录，技能实现修订交获授权维护者；next 选择下一有效动作，保留来源与变更理由 |

**状态不能互相代替**：可讨论不等于准予实施；值得小范围验证不等于价值成立；设计可开工不等于已实现；源码生成不等于已运行；首跑不等于可复跑；小样本通过不等于生产稳定；本人核对或 AI 评审不等于讲师、客户或有权者批准。

## 总技能的项目能力与课内边界

以下能力服务真实 FDE 项目，需要时可以调用。它们在总包中可用，**不表示本课新增完整商务、后端开发或生产部署课程**，也不要求所有学员完成商业项目全流程。

| 项目问题 | 对应独立模块 | 与课堂的关系 |
|---|---|---|
| 服务类型、客户信任、线索与售前投入 | [client](zhxbai-fde-client/SKILL.md) | 可支持机会讨论；完整获客经营不由本课承诺 |
| 客户聊天原意、冲突和后续问题 | [chat](zhxbai-fde-chat/SKILL.md) | 可作证据分析练习；不读心，不自动联系客户 |
| Demo/POC 范围、效果记录、转正式 | [poc](zhxbai-fde-poc/SKILL.md) | 课内演示和小样本实操不自动算商业 POC 或正式项目 |
| 决定权、材料配合、身份与记录权限 | [team](zhxbai-fde-team/SKILL.md) | 只核对当前已确认角色与操作，不给只读项目添加写入或管理角色；老板支持不能替代权限实测 |
| 报价、合同、变更、付款与移交 | [deal](zhxbai-fde-deal/SKILL.md) | 项目按需使用；不默认增设合同财税法律课程或代作承诺 |
| 日常可靠性、接管、维护和复用 | [run](zhxbai-fde-run/SKILL.md) | 课堂可学证据和责任边界；生产稳定与维护另验 |
| 项目卡点、窗口和非线性推进 | [next](zhxbai-fde-next/SKILL.md) | 帮助选下一动作；不把课表顺序当真实项目固定流程 |
| 工程方案与实现证据评审 | [code](zhxbai-fde-code/SKILL.md) | 需要具体工程交接或既有代码/日志设计级评审时使用；不承担应用或业务 Skill 实现，也不因此扩成完整后端课 |
| MVP 产品设计评审 | [doc](zhxbai-fde-doc/SKILL.md) | 对现有稿做按阶段评审；可开工判断不代替上线或生产审查 |

## 必须由具体项目或教学团队提供的内容

讲师真实案例和行业规则、实际课表与人数、工具接入文档、账号权限、可分享样本、验收人、商业价格与维护承诺，均来自对应材料或有权者确认。未知就标未知；没有接口连通证据不称实接，没有预演记录不称教学准入通过。

本技能可以整理、解释、提出具体设计与条件建议、协调和评审证据，不能替代讲师评审、真实用户验证或专业法律、财税与行业安全判断。文档生成不自动授权外发、安装、发布、业务写入或公开客户资料。
