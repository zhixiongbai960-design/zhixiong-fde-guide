# 当前题面 C1

我是内部D，只审材料，不写代码。只读员工个人排班范围已确认，但开发说明只写“服务端已鉴权”，没给查询过滤逻辑、接口片段或普通员工测试。能据此判断已经防住跨员工读取吗？请给短结论和最小需要的证据，不假定代码有漏洞，也不申请权限。

# 逐字答案

不能据此判断已经防住。当前只能记为“跨员工读取隔离的证据不足、未验证”，不能认定已有漏洞。“服务端已鉴权”没有说明是否对本次查询的数据归属做了限制。

最小补证由开发方提供，你只审材料：
1. 实现依据：当前版本的相关接口与查询过滤片段，能看清身份来自可信登录状态，以及如何把读取范围限定为当前员工本人；不能只凭请求传入的员工编号放行。
2. 普通员工实测：同一版本下，员工 A 从实际交付入口查本人排班成功；尝试指定员工 B 或更换排班记录标识时，不能读出 B 的数据。若已有列表查询，也需证明列表仅返回本人记录。只覆盖现有只读入口。
3. 可核对记录：上述测试的版本、环境、普通员工身份、时间、步骤、预期与实际结果，以及脱敏请求/响应或日志。越权反例要检查返回内容未泄漏他人数据，不能只看“拒绝”提示；模拟和未执行项单列。

补齐后再判断这些已测入口是否符合范围，不能把一次测试通过扩大为全面安全结论。
