# client round 1
## Raw request
客户已有工具不会用但没有预算，是不是伪需求？我该卖完整系统还是先做什么？
## Actual response
不能仅凭没有预算就判定是伪需求。这里至少有一个明确的能力缺口：客户已有工具却不会用。它可能是真痛点，但目前还不是可以按订单投入交付的机会。

先别卖完整系统。优先确认现成工具是否足够完成一个具体业务任务；如果够用，候选服务是培训或陪跑，承诺是让员工拿自己的任务跑通，并能检查结果，而不是交付新系统。只有证实存在工具能力或集成缺口，才讨论实施；若缺的是选方向，则做咨询。

建议先做一次低成本初谈：请客户说清最近一次实际卡住的任务、现在怎么做、为什么现在想解决，以及谁能协调人员和预算。你据此给出一个边界清楚的小步方案。专门备课、带练和持续答疑应另谈目标、范围和费用，不默认免费开发或免费陪跑。

如果客户愿意提供必要材料、安排业务人员，并推动预算，可以继续细化；痛点真实但暂时没资源，就保持联系，约定在什么条件出现后再推进。若只索要完整方案却不提供背景、不参与，就暂停深入投入。眼下的下一步是由客户选一个真实任务、明确推进人，你判断“教会什么”及所需投入，不是先承诺一整套系统。
