# design round 1

## Actual request
我已确认本地CSV精确筛选high/open后本人核对，不联网。给最小组件/输入输出/异常方案，不要强加API数据库。

## Actual Chinese response
建议用一个本地确定性筛选器，加一个本地结果查看入口。无需 API、数据库或云模型。下面是候选设计，列名和输出字段尚未给出，不把它称为可直接开工的定稿。

最小流程：你选择本地 CSV → 本地校验 → 按两个条件同时满足进行精确筛选 → 本地显示结果 → 你本人核对。

组件与职责：
- 本地筛选器：读取 CSV、校验字段、执行精确比较；不让模型猜分类或补值。
- 本地展示：显示筛选结果、匹配数量或停止原因；不改源文件。建议默认只展示，不新增导出文件步骤。
- 你：选择文件、确认字段映射及异常处理口径，核对结果。
- 如使用现有本地 Agent + Skill，Agent 只组织操作，Skill 记录方法与边界，执行仍交给确定性工具；它们不是完成这次筛选的额外必需系统。

输入与输出：
- 输入：本地 CSV 路径，以及“对应 high 的列”和“对应 open 的列”的明确映射。
- 规则：两列分别等于 high、open 才匹配。建议保持精确字符串比较，不自动改大小写或去空格；相关口径需写明。
- 输出：建议先显示匹配记录和数量，具体保留整行还是仅指定字段待你确认，不能擅自假定字段名。
- 数据边界：真实 CSV、原文及筛选结果均留本机，不能通过工具输出、日志或模型上下文回传云端。若运行环境无法保证，就只用合成样例设计，不处理真实数据。

异常方案（建议，待核对）：
- 文件不可读、编码或 CSV 结构无法解析：停止，不猜编码后悄悄继续；显示明确原因，由你修正或指定格式。
- 缺必要列、关键值为空、值不在已确认合法枚举内：停止并提示本地行号与字段。完整合法枚举目前未知，不把 high/open 两个筛选值当作所有合法值。
- 零匹配：正常显示 0 条，与读取失败区别开。
- 重复记录：不自动去重，先保留并提醒，避免擅改结果。

设计推演，尚未实测：合成行 high/open 应保留；high/closed 应排除；medium/open 应排除。这里 closed、medium 仅作候选测试值，须纳入确认的合法枚举后才可期待正常排除。空值、缺列应按确认的异常策略停止。你逐条对照预期及实际输出，并检查源文件未被改动、没有网络传输。

已确认：本地 CSV、high 与 open 同时精确匹配、本人复核、不联网。
待确认：实际列映射、输出字段、合法值全集及异常策略。
实现顺序：确认这些数据口径 → 本地读取与校验 → 精确筛选与展示 → 合成样例验证 → 在满足本机数据边界的环境里由你核对真实样例。
