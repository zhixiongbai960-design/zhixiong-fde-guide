## 2. 数据库迁移设计交接，非可执行迁移

在没有现有表结构、约束、存量数据和迁移框架的情况下，不能把一份猜测的 DDL 称为“可直接替换”。实施者应按以下逻辑变更落到实际迁移工具中：

- **持久化幂等记录**：保存操作者、操作名、request_key、目标申请、请求指纹、处理结果及必要时间信息。对前述键作用域建立唯一性约束。成功结果必须能原样重放，生命周期须覆盖所承诺的重试窗口，不能只存于进程内存。
- **事务边界**：将申请更新与幂等完成结果纳入同一次原子提交。若实际组件无法满足，先报告设计阻塞，不用异步补写冒充已经保证一致性。
- **权限数据**：复用管理员维护的责任表，不从客户端审批请求新增或变更设备责任。核对审批期间权限变更的并发一致性方案。

- **回退**：回退应用不等于撤销已经生效的审批。保留幂等与审计证据，避免清表重新放行重试；c7 有已知失败，不能默认作为安全回退版本。
