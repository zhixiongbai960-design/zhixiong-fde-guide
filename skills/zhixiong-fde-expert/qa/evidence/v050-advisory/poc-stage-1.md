## 实际业务答复（原文）

# 旧工单摘要交班 POC：本轮验证设计与判断

当前可以继续做有边界的验证，但不能宣布真实 POC 成功，也没有依据直接转正式。业务问题需要真实工作证据；本演练只有虚构记录，以下只能形成验证设计和演练观察，不能替代真实系统、真实材料与实际交班的验证。

## 1. 验证问题与范围

本轮集中回答一个问题：**在获准读取的旧工单材料中，摘要能否让交班人员看清需要接续处理的事情；哪些内容可以直接采用，哪些仍须回看原文、补充信息或人工重写？**

请业务方用具体交班任务说明“必须知道什么”，例如关键异常、当前处理状态、处置结论及待接续事项。这些是待业务确认的检查维度，不是替双方新增的验收承诺。重点分辨：

- 原文有依据，摘要是否保留了交班需要的信息。
- 原文缺依据时，摘要是否明确指出未知，以及人工能否据此知道该补什么。
- 在允许人工复核的前提下，剩余补位是否有业务价值、是否能持续承担。

不为这次验证新增前端、自动交班或写入能力。工程团队负责约定读取入口的准备与必要链路实施；本方案负责验证设计和证据评审，不执行接口开发或外部操作。

开始前的六项状态如下：

| 项目 | 已知约定 | 需核对或仍待确认 |
|---|---|---|
| 验证问题 | 判断旧工单摘要能否支持人工交班 | 交班所需关键信息及实际采用理由，由业务反馈逐步明确 |
| 工作与交付 | 限定20条获准样本、只读、给人工交班使用；工程准备读取入口 | 对照已商定方案核对必要链路、交付清单和完成证据。下文的记录、批次建议不自动成为新增合同义务 |
| 双方配合 | 业务方提供样本，每天20分钟反馈；工程准备读取入口 | 读取权限、环境条件及结果确认人，题内未提供具体信息 |
| 期限与依赖 | 3天 | 具体起止、样本和入口到位时间及依赖未满足时的安排，题内未提供 |
| 费用与支付 | 一口价6000元；40%启动、60%交付约定工作后 | 对应2400元、3600元。题内没有付款、到账或交付确认事实，本演练不发生付款 |
| 正式项目抵扣 | 未定 | 保持待确认，不默认抵扣或不抵扣 |

## 2. 把“工作完成”与“效果可用”分开

**工作完成看履约证据。** 是否按约使用样本、执行必要只读链路、保留约定记录并交出可检查的成果，需要逐项核对。当前只有前5条的概述，真实系统链路尚未执行；不能把它写成真实链路已验证。若真实链路属于约定工作，这部分就是未完成，而不是“验证出了不可行”。本演练不能执行它，应如实保留缺口。

**效果判断看具体输出与使用差异。** 现有观察只能支持以下窄结论：

- 3条被完整采用：说明这3条演练结果得到采用，不能推断日常样本均可用。仍需关联原始输出和采用理由。
- 1条遗漏关键异常，业务人员补写：是明确需要重做的结果。保留原文证据、原始摘要及补写内容，检查异常在什么环节丢失；原因未查清前，不直接归咎于模型，也不能把补写后的成果记成系统一次完成。
- 1条原文缺处置结论，摘要写“未知”：不能仅因写了未知就判摘要错误，也不能认定交班已经够用。需问业务方：这个未知是否阻碍接班，是否需要追问或回查其他材料；若需其他资料，还要确认是否在本次授权和范围内。

工程挑过样本，存在选择偏差；没有计时、重试记录，人工和运行成本均未知。不能把缺日志当成零重试、零人工，也不能据此算准确率、省时收益或宣称无人值守。既往日志若不存在，就标缺失，不能补造；后续重跑是新的试验，不能覆盖原始结果。

6000元对应已约定的验证工作，不是效果保证。效果不理想与工作未交齐是两件事；既不能用几条被采用证明尾款条件已满足，也不能因为效果尚未知就改写原付款安排。

## 3. 逐条记录表字段

建议每条样本一行主记录，原文、输出和修改版本用编号关联；必要时另列每次重试，避免只留下最后一次成功结果。

| 字段组 | 应记录的内容 |
|---|---|
| 样本与选择过程 | 样本ID、来源及版本、授权范围、是否虚构；谁选取、选择规则、是否预筛、剔除原因 |
| 交班任务与输入 | 这次要接续什么工作、实际读入的材料范围、原文是否缺页或缺结论、关键异常所在证据位置 |
| 运行条件 | 入口和环境、读取是否成功、只读权限与实际取数范围、摘要规则或配置版本、未执行的链路 |
| 原始输出 | 首次输出全文及版本、生成时间、与原文证据的对应关系；保留失败输出 |
| 采用部分及原因 | 业务采用了哪些句段、用于什么判断、为什么够用；反馈人和日期 |
| 重做部分及原因 | 遗漏、误述、无依据内容或表达不清；人工具体改动及原文依据，最终交班版本单独保存 |
| 人工与重试 | 谁筛选、提示、复核或补写；重试次数、原因和各次输出；开发者是否现场修正 |
| 耗时 | 生成、人工复核、补写、重试及等待分别记录。已有记录缺失就填“未记录”，不推算省时 |
| 异常与未确认项 | 信息缺失、状态冲突、读取失败等；是否影响交班、采取了什么人工措施、仍需补什么证据 |
| 结论与后续 | 本条支持继续、调整还是暂缓的理由；适用条件、下一步及责任方。新增功能另列候选，不混入本次义务 |

## 4. 下一批样本与异常策略

**先修复证据组织，再扩大观察。** 为前5条补齐能够核实的输入、原始输出和业务修改对应关系，标出无法找回的运行记录。优先复盘“漏关键异常”和“原文缺结论”两条，确定业务不能接受的差异到底是什么，不先增加功能或更换模型。

**其余最多15条仍在20条获准样本范围内。** 建议分两轮推进，具体分配根据现有样本覆盖情况与剩余时间确定：

1. 一轮检查普通交班任务。先登记剩余样本清单，再按固定顺序或预先确定的抽取规则取样，避免工程人员只选容易成功的案例。记录该规则及无法纳入的原因。
2. 一轮针对已发现风险。在获准样本确有相应内容的前提下，覆盖关键异常容易被长叙述掩盖、处置结论缺失、状态或时间线有冲突等情况，并保留普通样本作对照。风险定向选取必须明示，不把这组结果当成业务中的发生比例。没有相应样本就列覆盖缺口，不虚构已经测过。

本演练所有记录均为虚构，只能验证检查办法与记录方式。即使增加合成异常案例，也不能将其记为真实业务覆盖，更不能擅自超过本轮样本或投入范围。

异常处置建议如下，需由业务方确认后作为检查依据：

- **原文有关键异常而摘要漏掉：** 本条先由人工补齐后使用，保留原始失败结果。检查是否未读到材料、抽取范围错误、规则未体现交班重点或输出遗漏，再提出针对性调整与复测。
- **原文没有处置结论：** 明示未知，不推断已处理或已关闭；标出待核实事项，由交班人员决定是否补资料或暂不依赖摘要。
- **内容相互冲突：** 保留冲突和来源，不默默替业务选一个结论。
- **读取失败、材料不全或权限不符：** 记为链路或输入问题，不凭空生成结果；转人工原流程。此项当前只是待验证策略，不能写成已实现功能。

每天20分钟反馈优先看高风险差异、人工改动和仍说不清的事项，不要求业务方给每条打统一分数。修改规则后，既复测原失败案例，也检查普通案例是否受影响，重试如实记录。3天内若条件不到位，交付已完成部分和明确缺口，由双方选择等待、缩范围或另约验证；不自动延长、加价或宣布全部完成。

## 5. 转正式项目的条件

现阶段不建议直接转正式。可以在补齐证据后提出有条件的继续建议，最终由业务负责人和投入负责人决定。至少需要确认：

1. **真实工作证据成立。** 在另行具备真实条件的验证中，必要只读链路、授权材料和人工交班流程实际跑过，有输入、原始输出、采用和重做记录。本次虚构演练不能替代这一步。
2. **业务判断可执行。** 关键异常遗漏、信息缺失及冲突如何处理有共同认识；哪些必须人工复核、谁接手、何时不能依赖摘要说得清。标准来自实际差异，不强造准确率或省时阈值。
3. **持续运行条件明确。** 核对正式使用者和入口、读取范围与权限、工单状态和异常处理、资料版本及供数责任、失败恢复和人工接管。试用授权不自动覆盖长期使用。
4. **范围差异和测试责任清楚。** 列出沿用、适配、新增三类：有证据可用的记录结构或已验证成果可以沿用；入口、数据字段、权限或版本变化需适配验证；新增写入、自动交班等能力应单列候选，未经确认不纳入。真实链路尚未执行，不能先列成“已完成可复用”。
5. **投入和新约定确认。** 业务方选择保留人工、增加能力或缩小范围；工程方据实际差异估算实施、测试、部署、交接及支持工作。直接复用不重复计开发，适配和验证如实计。正式价格不等于6000元，抵扣仍待约定，也没有依据套用收益比例报价。

最终结论应分别写两句：**“约定工作完成到哪里、还缺什么”**和**“现有证据为何支持继续、调整或停止”**。前者不能被效果好坏替代，后者不能被已经投入的钱替代。
