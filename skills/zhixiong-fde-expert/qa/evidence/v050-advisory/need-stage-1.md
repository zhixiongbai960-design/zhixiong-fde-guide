# 器材交班逾期借用核对清单 MVP 需求规格

版本：v1.0  
日期：2026-11-10

## 1 场景与现状目标

**一句话需求：**作为器材管理员，在交班前，需要从借用记录中找出超过约定归还日且仍为“借出”的条目，并把资料异常条目单列，以便自己核对后人工联系借用人。

- **现状 As-is：**交班前查看借用记录 → 逐行翻表 → 检查约定归还日和状态 → 找出需要核对的条目 → 人工联系借用人。
- **已知问题与依据：**最近一次逐行翻表时漏看了表尾两条。这是本人提供的经历，未独立验证。
- **具体卡点：**从记录中逐条发现符合条件的条目时出现漏看。是否仅由排序导致尚未验证，不能把排序调整视为已经证实有效的解决方案。
- **目标 To-be：**读取本次完整输入 → 按明确规则逐条分类 → 给管理员展示逾期待核对条目与资料异常条目 → 管理员核对原始记录 → 人工处理后续联系。
- **预期变化：**管理员从逐行寻找候选条目，转为核对已筛出的候选和异常。是否减少漏看、是否节省时间，留待试跑观察，不承诺效果数值。

## 2 最小范围

**已确认包含：**

1. 只读四个输入字段：record_id、item_name、due_date、status。
2. 按本地日历日判断；本次“今天”为 2026-11-10。
3. due_date 早于今天且 status 为“借出”时列入逾期待核对清单。
4. 缺日期或非法状态的条目单列待核对，不猜测或补齐值。
5. 结果只供器材管理员本人使用，由其人工核对和联系借用人。

**本版不包含：**

- 自动催还、自动发送消息、查找或采集借用人联系方式。
- 修改借用记录、自动改状态、补日期、写回原表。
- 多角色审批、管理后台、账号体系、支付或统计平台。
- 定时运行、自动同步、生产系统接入及对外发布。
- 把“排序是唯一原因”或“可以消除漏看”当成已验证结论。

**设计建议：**结果分为“逾期待核对”和“资料异常待核对”两区，附本次判断日期及处理完整性说明。具体展示载体尚未确认；以下输出字段是交接建议，不扩大业务范围。

## 3 输入与字段规则

输入来源是借用记录。现有平台、文件格式、字段类型与接入方式未知；本题没有可连接的真实业务系统。

| 字段 | 用途 | 已确认规则及边界 |
|---|---|---|
| record_id | 定位原始借用记录 | 原样保留，不自行生成或改写。是否唯一、是否可能缺失尚未确认。 |
| item_name | 让管理员识别器材 | 原样保留，不推断名称。题内三个示例未提供具体名称。 |
| due_date | 约定归还日 | 以本地日历日比较。缺失时进入资料异常待核对，不猜日期。源字段格式尚未确认。 |
| status | 借用状态 | 合法值仅为“借出”“已归还”。其他值均不得自动映射为合法状态，应进入资料异常待核对。 |

### 日期与分类顺序

1. **先检查资料异常。**缺 due_date 或 status 不属于两个合法值时，将该行放入“资料异常待核对”。同一行有多项异常时一并列明，不在两个清单中重复列为已确定逾期。
2. **再判断正常条目。**资料可用于判断时，只有 due_date 早于 2026-11-10 且 status 等于“借出”，才进入“逾期待核对”。
3. due_date 等于今天不列入；晚于今天不列入；状态为“已归还”的有效条目不列入。
4. 缺日期或非法状态的规则适用于所有条目。例如“已归还”但缺日期，也应单列资料异常，不能因为已归还就跳过异常检查。
5. 本次固定使用给定的 2026-11-10，不以运行机器的 UTC 日期替代。未来运行时，本地日历日来自何地、何种时区及日期取得方式，需要在接入前明确。

**补充工程建议，尚未确认为业务规则：**

- 日期有值但不是有效日期、格式有歧义或无法解析时，也转人工核对，不静默猜测年份、月日顺序或进行模糊转换。
- record_id 缺失、重复或 item_name 缺失时保留原始行并提示定位风险，不自动合并、去重或补值。是否阻止该行进入逾期候选，需要在实际输入出现此类情况时确认。
- 日期输入宜采用能明确表达完整日历日的格式；具体格式由来源决定，本规格不声称原表采用某种格式。

### 处理流程

管理员提供本次输入 → 检查输入能否完整读取 → 逐条检查日期与状态 → 按规则分类 → 生成清单和异常说明 → 管理员对照原记录核实 → 管理员自行联系借用人。

遍历应覆盖本次输入的全部记录，包括表尾。输入是否包含全部业务记录，仍需管理员与接入方确认；“完整处理收到的输入”不等于“已经证明业务源没有遗漏”。

## 4 输出与人工接管

### 建议的输出结构

**运行说明：**判断日期、本次输入来源说明、是否完整读取与处理、输入条数和各类条数。条数属于核对辅助信息，不是业务效果指标。

**逾期待核对区：**record_id、item_name、due_date、status，以及列入依据“归还日早于判断日，状态为借出”。

**资料异常待核对区：**原始四字段及具体异常原因，如“缺归还日期”“状态不在允许值中”。保留异常原值；不将异常条目标为已确认逾期。

默认不要求把所有正常排除条目再列一遍。为核对覆盖情况，可提供“逾期待核对／资料异常待核对／正常不列入”数量汇总。排序仅影响展示，不改变是否列入；本版不把排序改进作为业务效果前提。

### 人工负责与接管位置

- **输入阶段：**管理员确认材料属于本次核对范围。读取失败、无法确认完整性或字段对应不清时，暂停输出“完整清单”，由人工检查材料。
- **异常阶段：**管理员回查原始资料，确认缺日期及非法状态；工具不代填、不猜测。确需修正原始记录时，由有权人员在原流程处理，本版不写回。
- **结果阶段：**管理员对照原始记录核对候选条目，确认是否需要联系借用人。清单不是自动催还决定。
- **后续阶段：**管理员自行取得联系信息并联系借用人，工具不查找、不发送、不保存联系记录。
- **失败回退：**可重新提供完整输入后再生成；在问题解决前恢复人工查表。失败或部分结果不得伪装为“没有逾期条目”。
