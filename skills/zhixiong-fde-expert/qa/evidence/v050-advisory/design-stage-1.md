## 合成题面（原文）

以下是完全合成的演练案例，不含真实客户、账号或私人资料。只使用题内事实；没有真实外部系统可操作。

合成项目规格S1已确认：内部资料审核员只读查找自己被分配的资料包，按编号显示标题、版本、缺失项；不得看到其他审核员的资料、文件正文或联系人字段，不做新建修改删除。输入reviewer_identity由登录系统验证；资料有packet_id、assigned_reviewer_id、title、version、missing_fields。无匹配正常显示空结果。查询服务是否已有尚不清楚，不能假定API已接通。没有实时性要求，先用已授权的合成快照验证。
请给具体最小架构：一个样例流程、组件/人分工、查询输入输出契约、角色×对象×字段权限、空结果/越权/数据过期异常、正常和拒绝用例、工程交接与最先验证假设。说明是否需要新增数据库或API及理由，可以保留平台未知。


## 实际业务答复（原文）

# S1 最小架构设计

**本轮采用“可信身份上下文 + 本地只读查询与权限投影 + 已授权合成快照”，不新增数据库，不假定已有 API。** 本交付是设计与工程交接，以下用例均为设计推演，未接通登录系统、查询服务或运行实现。

## 1. 范围与最小连接关系

已确认的业务能力只有：审核员查找分配给自己的资料包，逐条显示编号、标题、版本、缺失项；无匹配显示空结果。没有新建、修改、删除、文件正文查看或联系人查看功能。

连接关系：

审核员 → 最小查询入口 → 可信身份上下文 → 本地只读查询组件 → 已授权合成快照

本地查询组件 → 按身份筛选 → 允许字段投影 → 结果校验 → 审核员界面

- **查询入口**：发起只读查询，展示四个允许字段、空结果或通用错误。不得提供“切换其他审核员”控件。按 `packet_id` 稳定排序展示，不据此推断编号的业务含义。
- **身份上下文**：使用 S1 规定的、由登录系统验证的 `reviewer_identity`。真实平台的传递方式仍未知。合成验证可使用明确标记为测试输入的可信身份夹具，不把夹具当作真实登录实现。
- **本地查询组件**：用确定性逻辑完成身份边界检查、归属过滤、字段投影及数据校验。不能只靠界面隐藏字段，也不能靠提示词限制越权。
- **合成快照**：只读输入，含题内五个源字段。查询路径不得修改它。快照的版本与有效性由独立的验证记录标识，不冒充已存在的业务字段。
- **Agent / Skill**：本轮可辅助组织设计、说明结果和核对用例；Skill 是方法与边界，不是查询引擎。这个查询不需要运行时模型推理。若以后采用 Agent 对话入口，它也只能接收已完成权限过滤和字段投影的结果，不能先读取整个快照再自行决定向谁展示。

每个组件均对应 S1：身份与过滤防止跨审核员访问，投影排除禁止字段，结果展示支持资料审核，快照支持无实时性要求的最小验证。全文检索、RAG、多 Agent、在线文档、写入接口均不进入本轮范围。

## 2. 一个样例走通

以下值只是解释设计的合成示例，不是额外项目事实。

快照包含：

| packet_id | assigned_reviewer_id | title | version | missing_fields |
|---|---|---|---|---|
| P-001 | R-A | 合成资料包甲 | v1 | [] |
| P-002 | R-B | 合成资料包乙 | v2 | [] |

流程：

1. 审核员发起“查看我的资料包”。查询入口不要求其自行填写审核员身份。
2. 身份适配层交付可信 `reviewer_identity = R-A`。缺失或未经验证则停止，不读出资料。
3. 查询组件确认所选合成快照仍获准用于本次验证，再以 `assigned_reviewer_id = R-A` 过滤。
4. 组件只投影 `packet_id、title、version、missing_fields`。`assigned_reviewer_id` 仅用于内部判定，不进入返回结果。
5. 返回 P-001 的四个字段。P-002 不进入响应，不显示“另有一条无权查看”，也不返回全快照总数。
6. 审核员核对自己需要处理的编号、版本和缺失项；验收者用合成样例的预期结果核对身份隔离及字段边界。审核员随后如何补齐资料不属于本轮功能。

## 3. 查询输入输出契约

这是**逻辑调用契约**，可在本地组件边界实现，不表示存在某个 URL、SDK 或已连接的服务。

### 输入与约束

| 项目 | 来源与约束 |
|---|---|
| reviewer_identity | 唯一业务查询依据；由可信登录上下文提供的非空身份标识，不接受客户端正文或查询参数覆盖 |
| 合成快照选择 | 由验证配置固定，普通审核员不能传入任意文件路径或选择其他数据源 |
| 身份映射 | 与 `assigned_reviewer_id` 使用同一身份命名空间、精确匹配；不得用显示名模糊匹配，不擅自大小写转换或补全 |

最小请求不增加按其他审核员、联系人、正文等筛选条件；按单个编号检索也不是本轮必须增加的输入能力，当前先按编号展示本人的资料清单。

### 正常输出示例

```json
{
  "status": "ok",
  "items": [
    {
      "packet_id": "P-001",
      "title": "合成资料包甲",
      "version": "v1",
      "missing_fields": []
    }
  ]
}
```

无匹配为 `{"status":"ok","items":[]}`，是正常结果，不是权限错误或系统故障。

拟定字段约束如下，属于待实现、待用快照核对的契约，不声称现有数据已满足：

- `packet_id`：非空、不透明标识；单份快照中每个编号只对应一条记录。不凭编号推断归属。
- `title、version`：保留源值，不让模型补全或改写。源数据明确缺失时可返回 `null`；该可空约定须在交接时与快照表达核对。版本不默认符合语义化版本号，也不靠字符串大小选“最新”。
- `missing_fields`：字符串数组，保留已确认的缺失项表达；空数组只表示源数据明确没有缺失项，不能用于掩盖解析失败。具体条目字典尚未提供。
- 对缺失项条目也实施禁止字段边界：不得携带联系人字段名、联系人值或正文片段。验证前核对条目字典及显示文案；发现禁止内容或无法确定其可展示性时返回数据不可用，不原样输出、不悄悄改为空数组。
- 响应只允许这四个业务字段。源数据意外多出字段时不自动透传；禁止把原记录、调试对象或 `assigned_reviewer_id` 附在响应中。

### 错误语义与重复处理

拟定错误码只表达当前查询状态：

- `ACCESS_DENIED`：没有可信身份、身份来源被篡改或试图覆盖身份上下文。响应不含资料信息。
- `INVALID_REQUEST`：请求包含不支持的查询参数或操作，不进一步探测目标资料是否存在。
- `DATA_UNAVAILABLE`：快照缺失、格式不合法、归属字段不可靠、编号冲突或展示内容不符合边界。
- `SNAPSHOT_INVALID`：快照已被明确标记失效，或其分配关系已不能作为本次访问依据。

错误响应不附带被拒绝记录、其他审核员身份或隐藏资料数量。只读查询在相同可信身份与同一有效快照下应返回相同结果，无写入副作用。重复编号不擅自去重或取最大版本，交给资料确认者核对。确定性错误不自动重试；快照或配置修正并重新获准后再查询。本轮没有外部写入，也不设计写入重试。

## 4. 角色 × 对象 × 字段权限

| 角色 / 执行身份 | 对象 | 字段与操作 |
|---|---|---|
| 审核员 | 分配给自己的资料包 | 只读 `packet_id、title、version、missing_fields`，并受显示内容校验约束 |
| 审核员 | 分配给其他审核员的资料包 | 不可见任何字段，也不暴露其存在性、编号或数量 |
| 审核员 | 任意资料包的 `assigned_reviewer_id` | 不作为展示字段或可编辑字段提供 |
| 审核员 | 任意资料包的文件正文、联系人字段 | 禁止读取和展示；本轮快照不需要包含这些内容 |
| 审核员 | 任意资料包 | 新建、修改、删除全部禁止 |
| 查询组件的执行身份 | 本轮获准的合成快照 | 内部只读五个源字段，归属字段只用于授权判定；只向审核员返回允许投影，不获得外部系统权限 |
| 资料 / 权限确认者、验收者（人员待定） | 验证配置、合成样例、预期与结果证据 | 作为工程职责核对范围和有效性，不由本设计自动授予真实系统管理权或全库读取权 |

权限必须在查询边界实施，而不是返回所有记录后让前端过滤。身份上下文与结果之间不使用跨身份共享的结果缓存。若未来需要缓存，应把身份和快照版本纳入隔离条件并另行评审，本轮不新增缓存组件。

## 5. 状态与异常边界

主路径：请求到达 → 身份可信 → 快照可用且有效 → 按归属筛选 → 允许字段投影与校验 → 返回结果 / 正常空结果。

- **空结果**：可信身份在有效快照中没有匹配项，显示“当前快照中没有分配给你的资料包”。不能把读取失败、过滤规则失败当成空结果。
- **越权**：客户端试图替换身份或请求被禁止操作，拒绝。有效身份正常查询时，其他人的记录只被排除，不告诉用户其是否存在。两种情况都不得泄漏对象信息。
- **数据过期**：S1 无实时性要求，不能凭快照日期较早就擅自设置“24 小时失效”等门槛。应区分：
  - 快照仍获准用于此次合成验证，只是并非实时资料：可继续，明确显示“合成快照结果”，只有确有记录时才标示快照日期。
  - 快照被撤销、明确过期，或已知分配关系变化但尚未核对：停止查询，请资料 / 权限确认者提供有效快照。不以“无实时性要求”为理由继续使用失效授权。
  - 是否有效无法确定：该快照不能支撑真实权限验收；只保留明确获准的合成推演，不声称验证了真实权限。
- **数据冲突或损坏**：缺失归属标识、重复编号对应冲突记录等，停止本次查询并给出通用错误。错误详情留在受控验证证据中，不把其他审核员记录显示出来。
- **组件不可用**：查询失败时不回退到让审核员或 Agent 打开整个快照，不绕过过滤。由执行者修复或人工核对合成预期。

## 6. 正常与拒绝用例

以下为待执行用例，尚无运行通过证据。验收时同时检查响应内容、界面和调试输出，防止仅界面隐藏、响应仍泄漏。

| 用例 | 输入 / 条件 | 预期与核对方式 |
|---|---|---|
| 正常本人查询 | 可信 R-A，上述有效样例快照 | 只返回 P-001 的四个允许字段，与样例逐字段比较 |
| 正常另一身份查询 | 可信 R-B，同一快照 | 只返回 P-002；与 R-A 结果隔离，不串用历史结果 |
| 正常空结果 | 另一个可信测试身份，无分配记录 | `ok` 与空数组，界面正常空态，无全局总数 |
| 正常缺失项展示 | 本人记录包含经确认可展示的非空缺失项列表 | 原样显示允许条目，不补写缺失内容；具体条目待快照字典确认后实例化 |
| 拒绝不可信身份 | 未认证或无可信身份上下文 | `ACCESS_DENIED`，无资料结果 |
| 拒绝身份覆盖 | 可信上下文为 R-A，客户端另传 R-B | 拒绝请求，不转为查询 R-B；核对无 P-002、R-B 或隐藏记录信息泄漏 |
| 拒绝额外字段 / 操作 | 请求正文、联系人、指定其他审核员或写操作 | 不支持并拒绝；无正文、联系人返回，无数据变更 |
| 拒绝隐蔽字段泄漏 | 本人记录的缺失项包含禁止内容 | `DATA_UNAVAILABLE`，不回显问题条目，不把错误伪装成“无缺失项” |
| 失效快照 | 快照明确标记失效或归属已被撤销 | `SNAPSHOT_INVALID`，不继续返回旧分配关系下的资料 |
| 冲突快照 | 同编号有冲突版本或归属、归属字段缺失 | `DATA_UNAVAILABLE`，不猜测应取哪条，不扩大可见范围 |
| 本地读取失败 | 已配置快照无法读取 | 通用不可用提示；不声称已访问 API，不转去尝试未知服务 |

## 7. 是否新增数据库或 API

**现在两者都不需要。** 数据只读、无实时性要求、已允许先用合成快照，且没有确认存在必须共享的在线状态。增加数据库不会自动解决归属授权，增加 API 也不是权限正确的前提。

先实现一个可被测试的本地查询边界即可。若后续确认已有查询服务，先核对其身份传递、对象过滤、字段投影、错误语义和连接授权，再决定是否复用；目前将它标为“未知、未连接”，不编造接口地址。

只有后续明确需要多用户在线访问、实时更新分配关系或持续共享数据时，才评估服务化和持久化。届时应优先复用已获准且能满足权限要求的能力，而不是默认新建。新增连接、数据同步和运行维护属于范围变更，需要补充来源、授权、失败替代及维护责任；本轮设计不批准这些新功能。

## 8. 工程交接、依赖与完成证据

本模块交付设计，不编写或委派编写业务实现。实际执行者、接收者与验收者均待指定。

实施顺序与依赖：

1. **资料 / 权限确认者**核对合成快照获准范围、身份命名空间、缺失项可展示字典、快照有效性规则。保留快照来源和版本记录；不把凭据写入文档。
2. **实现接收者**按上述契约建立可信身份边界、只读加载、归属过滤和字段投影。依赖第 1 步的字段与身份约定；真实登录适配方式未知时，只交付合成验证入口，不能宣称可生产开通。
3. **实现接收者**接入最小结果展示及错误状态，不增加外接服务、写操作或额外查询功能。
4. **测试执行者**使用两名审核员及无分配身份，执行正常、空结果、身份覆盖、字段泄漏和失效快照用例；检查客户端响应及调试输出，不只看截图。
5. **业务 / 权限验收者**核对业务显示与隔离结果，记录剩余未知项，并决定是否进入下一阶段。验收本轮不等于批准真实数据接入。

应交回的证据：所用合成快照版本与有效性说明、身份映射约定、输入与预期结果、实际返回结果、拒绝用例记录、允许字段清单检查、无写操作及未外接的核对记录。保存位置、访问者及清理时点由项目方确定；本轮不引入永久日志库。实际结果证据应只含获准的合成数据，不能依靠记录完整原始数据排查问题。

**最先验证的高影响假设：快照内的 `assigned_reviewer_id` 与可信 `reviewer_identity` 是同一身份体系，而且该快照的分配关系仍获准用于本次验证。** 由身份负责人和资料 / 权限确认者共同核对，人员待指定。先用 R-A、R-B 的交叉用例证明过滤依据与预期一致；若映射不明或分配关系失效，就不能声称权限设计已验证，即使界面能显示结果。

当前状态：S1 的只读范围与字段边界已确认；本地组件契约、空值表达和验证记录形式是本次提出的设计；真实平台、已有服务、快照有效性管理和具体负责人尚未知。可以据此准备合成验证，但真实系统实施与上线条件尚未确认。
