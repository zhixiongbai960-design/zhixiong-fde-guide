# 客户聊天与沟通判断

依据05、06、18、19及相关商业章节。帮助理解客户表达和下一步，不宣称看穿真实心理。

## 读原话而非读心

先识别记录时间、说话人及已知角色，区分本人原话、转述、转写不确定、后续修正。角色不明就标不明；老板/技术/采购等称谓不能自动证明其决策权。只摘对本次判断必要的短句，不大量复述客户隐私。

对每个核心判断分别给：原话与上下文 → 能支持的有限结论 → 可能解释及替代解释/反例 → 还缺什么 → 下一问题或验证动作。比如“预算以后说”支持预算未确认，不能直接断言没钱/白嫖；“回去问老板”支持需内部确认，不等于对方故意拖延。

客户想法分成明确目标、已承诺动作、犹豫/冲突线索、未表达部分。愿望不是承诺，“收到”不是范围确认；前后矛盾并列，先核对哪条是最新有效意向及其确认范围，不强行合成单一故事。不用未经校准的80%之类概率替猜测背书。

## 输出能推进沟通

按用户问题判断合作成熟度、范围/付费/配合/验收/权力风险，关联原文。给少量优先级最高的后续问题，说明每问会影响什么决定。对话式追问每轮只选一个最影响下一步的独立未知来问；不能把身份、所指范围、确认权限等可分别回答的问题用一个问号串起来。其余缺口可注明待核对，不同时索答。用户明确要会议提纲或核对清单时，仍按需列多个问题并说明用途。需要时给可发送的短草稿，但默认只是草稿，不自动联系客户、绕过直接合作方或对外承诺。

信息完整时也可给明确有限判断，不因不能读心就只说无法判断。说清目前证据足以做哪个行动，哪些仍为假设。后续新聊天只更新相关判断，保留改判依据，不把AI原推断当新的客户事实。

## 隐私和敏感信息

只分析与项目有关内容。记录含客户姓名/电话、合同/财务、账号、健康或未成年人等信息时，尽量用角色/代号和最小必要片段；不索取不必要敏感信息，不把私人数据加入技能原文/公开仓库/第三方工具。用户已提供的敏感事实可以在授权范围内必要地分析，但不能凭聊天推断健康诊断、人格、家庭、财务状况或未成年人的隐私属性。

若用户限制本机处理，遵守数据和工具回传边界；无法本机分析时请其提供脱敏必要片段，不先上传再说。不得保存密码密钥、复制客户名单或因分析需要自动传给外部服务。当前任务不授权外发、联系或写业务系统。
