版本：0.4.4（发布前验证记录：chat模块两响应及独立审阅、专家入口/跨方法两响应及独立审阅、专家构建与verify、46项包装/说明书测试均通过。实际发布状态以仓库提交为准） · 作者：白志雄 · 志亚科技出品

## 1. 它与《志雄 FDE 实战指南》是什么关系？

专家技能与[《志雄 FDE 实战指南》](https://github.com/zhixiongbai960-design/zhixiong-fde-guide)放在同一个 GitHub 仓库，但作为一个独立的、可安装的技能包提供。指南适合按篇阅读；专家技能让支持 Skill 的 AI 宿主按你当前的问题，读取指南和方法，帮助分析材料、形成方案、检查缺口和推进项目。

安装入口是仓库中的 [skills/zhixiong-fde-expert](https://github.com/zhixiongbai960-design/zhixiong-fde-guide/tree/main/skills/zhixiong-fde-expert)。这次不是新建仓库，也不代表已经发布 GitHub Release 或上架 Marketplace。实际分发方式是仓库中的技能目录，可随仓库 ZIP 下载。

名称分三种用途：

- 展示名称：`zhixiong-fde-Expert`，保留 Expert 的大写 E。
- 文件夹及 `SKILL.md` 内部 `name`：`zhixiong-fde-expert`，全部小写，不带空格。
- Codex 中的明确调用：`$zhixiong-fde-expert`。

角色名仍为“志雄”，是一位基于公开方法提供帮助的虚拟 FDE 专家、AI 助手，不是白志雄本人，也不代表本人背书。安装技能不修改你的账号或宿主显示名称。

## 2. 包里有什么，能帮你做什么？

本包包含 18 个方法、33 篇指南完整文字（32 篇编号正文加 05 加篇）、资料索引及 MVP 规格模板。18 个方法已经内置，不需要再安装 18 个独立模块。文字资料可在本地读取；正文引用的图片仍是在线资源，离线或网络受限时可能看不到图片，但不妨碍使用包内文字方法。

你可以让它帮助：

- 从客户原话中区分明确需求、推测和待核实问题。
- 梳理需求、限定范围，形成带假设和缺口的 MVP 规格。
- 规划 POC，检查验证标准、配合条件和转正式项目的门槛。
- 评审方案、设计文档、代码与测试证据，指出下一步应核验什么。
- 整理报价、变更、交付、维护和复盘中的业务问题。
- 按指南解释方法，准备课堂练习和教学案例。

它按当前卡点选择方法，不要求你从第一篇开始“通关”，也不应为了一个小问题强制启动整套咨询。

### 它不能替你保证什么？

它不能保证项目成功、收益、准确率、客户认可或法律效力。指南中的价格、付款比例和时间经验不是你的项目承诺，也不是通用行业标准。文档评审通过不等于组织批准、代码已经运行、生产环境验收或款项到账。

技能本身不提供模型服务、账号、API、联网能力、文件访问权限或生产系统连接。能否读文件、运行代码、访问网站，由宿主、模型服务及你的授权决定。它也不能仅凭聊天记录读出客户真实心理，不能代替法律、财税或行业安全专业人员作出正式结论。

## 3. 安装前先确认

1. 你的 AI 宿主支持加载 `SKILL.md`，并且能读取技能文件夹内的本地资料。只有普通聊天输入框、没有本地文件读取能力的产品，不等于支持这个技能包。
2. 宿主已经配置好可用的模型服务。模型的费用、隐私约定和使用限制遵循服务商及你的配置，本技能不附送模型服务。
3. 知道宿主指定的技能安装目录。下文提供 Codex 的本地目录；其他宿主以其官方文档为准。
4. 检查是否已安装旧总包 `zhxbai-fde` 或新总包 `zhixiong-fde-expert`。不要同时安装新旧总包，也不要直接覆盖已有文件。
5. 阅读许可。个人非商业学习、研究和试用适用免费许可；企业实际部署、内部业务提效、客户交付、付费培训等商业用途须事先取得书面授权。

本说明不承诺 WorkBuddy 或其他宿主已通过安装验证。具体验证范围请看[检查与版本记录](https://github.com/zhixiongbai960-design/zhixiong-fde-guide/blob/main/skill-source/docs/检查与版本记录.md)，不要把包装检查或示例回复当成宿主兼容性测试。

## 4. 推荐安装：下载 ZIP，只复制总包文件夹

1. 打开[仓库首页](https://github.com/zhixiongbai960-design/zhixiong-fde-guide)，选择 **Code → Download ZIP**。
2. 解压 ZIP。打开解压后的仓库根目录，找到 `skills/zhixiong-fde-expert`。
3. 将整个 `zhixiong-fde-expert` 文件夹复制到宿主的技能安装目录。不要只复制 `SKILL.md`，也不要把整个仓库、`skill-source` 或全部 `skills` 当作总包一起安装。
4. 对 Codex，本地安装目录为 `${CODEX_HOME:-$HOME/.codex}/skills`。默认即当前用户主目录下的 `.codex/skills`；设置了 `CODEX_HOME` 时应使用该值下的 `skills`。
5. 确认目标结构是“技能安装目录 / zhixiong-fde-expert / SKILL.md”，而不是多套了一层同名文件夹。
6. 开启新会话，再明确调用 `$zhixiong-fde-expert`。

### macOS / Linux：可选 Bash 复制命令

先在终端进入**刚解压的仓库根目录**，再在 Bash 中执行以下整段命令。命令遇到旧包或已有目标会停止，不覆盖、不自动删除、不自动迁移旧版。

```bash
bash <<'BASH'
set -eu
src="$PWD/skills/zhixiong-fde-expert"
skills_dir="${CODEX_HOME:-$HOME/.codex}/skills"
dst="$skills_dir/zhixiong-fde-expert"
old="$skills_dir/zhxbai-fde"

if [ ! -f "$src/SKILL.md" ]; then
  printf '%s\n' '停止：请先进入解压后的仓库根目录，确认 skills/zhixiong-fde-expert/SKILL.md 存在。' >&2
  exit 1
fi
if [ -e "$old" ] || [ -L "$old" ]; then
  printf '%s\n' '停止：检测到旧总包 zhxbai-fde。请先将它移到技能安装目录之外备份，再重新执行。' >&2
  exit 1
fi
if [ -e "$dst" ] || [ -L "$dst" ]; then
  printf '%s\n' '停止：目标 zhixiong-fde-expert 已存在。请先将现有包移到技能安装目录之外备份，再重新执行。' >&2
  exit 1
fi
mkdir -p "$skills_dir"
cp -R "$src" "$dst"
printf '已复制到：%s\n请开启 Codex 新会话，调用 $zhixiong-fde-expert。\n' "$dst"
BASH
```

“复制完成”只说明文件复制完成，不等于宿主已成功加载，也不是实际业务验证。不要在另一个安装进程同时修改这些目录时执行。

### Windows 或其他宿主

使用文件管理器手动复制整个 `zhixiong-fde-expert` 文件夹到宿主官方文档指定的目录。不必运行上面的 Bash 命令，也不要套用未经确认的 Windows 路径。先检查该目录有没有旧包或已有目标，存在时先移到技能目录之外备份。其他宿主的明确调用方式遵循其文档，不假定都支持 Codex 的 `$` 写法。

## 5. 第一次使用，先检查是否真的读到了包

在 Codex 新会话中发送：

> $zhixiong-fde-expert 请读取你安装目录中的 SKILL.md 和资料索引，告诉我当前版本、包含哪些资料，以及是否能够读取 references 下的正文。先不要联网，也不要修改文件。

核对它是否报告 `name: zhixiong-fde-expert`、版本 `0.4.4`，以及 18 个方法、33 篇文字资料。要求它说明实际读到的文件和内容；仅回答“已加载”不足以证明读取成功。如果宿主无法读取本地文件，应明确报告，不应根据技能名称猜测方法。

常见排查：

- 找不到技能：检查安装位置、文件夹嵌套层级，并开启新会话。
- 能识别名字却读不到方法：检查是否只复制了入口文件，是否缺少 `references`。
- 回答仍显示旧包：检查宿主配置的其他技能搜索路径，确保旧总包已移出可扫描目录，再开新会话。
- 图片打不开：先用本地正文继续；不要把图片联网失败误判为整个包缺失。

## 6. 四种可直接改写的用法

下面都是**示范提问，不是真实客户资料，也不是已执行测试记录**。练习可使用合成或获准脱敏材料；实际商业项目使用须先满足许可与数据授权要求。

### 例一：分析客户聊天

> $zhixiong-fde-expert 下面是一段合成客户聊天：“想先做个自动汇总工具，老板说可以，但财务暂时不愿提供明细。”请区分原话事实、你的推测和未知，找出最影响下一步的一项问题。先不要报价，也不要联系客户。

应核验：判断是否有原话依据；“老板同意”是否被错误理解成数据访问授权；有没有凭空补出预算、字段或工期。

### 例二：把需求整理成 MVP 规格草稿

> $zhixiong-fde-expert 我在做个人练习：将我手动导出的合成 CSV 汇总为周报，只读本地文件，不连接业务系统。请用包内模板整理一份 MVP 规格草稿，缺少的字段、统计规则和验收标准标为待确认；如果必须追问，每轮只问一个核心问题。

应核验：输入、输出、统计规则、异常处理和验收是否可核对；未知内容是否仍标为未知；有没有擅自增加系统接入或写入范围。

### 例三：评审设计文档是否具备开工条件

> $zhixiong-fde-expert 请读取我本轮指定的设计文档，检查它与已确认需求是否一致，列出阻止开工的问题和可以并行准备的事项。只做评审，不修改代码、不运行命令、不替负责人批准上线。

应核验：问题是否指向文档具体位置；缺陷和建议是否区分；“可准备”是否被误写成“已获批准”或“测试通过”。需要读取文件时，应补充你允许它读取的准确路径。

### 例四：为 POC 设置验证边界

> $zhixiong-fde-expert 用合成数据设计一个订单分类 POC 的验证方案。当前还不知道分类规则是否稳定，不能预先承诺准确率。请列出需确认的规则、样本边界、失败时怎么处理，以及什么证据足以讨论下一步。

应核验：是否先明确未知和验证对象；有没有编造效果数字；演示、验证完成和转正式项目的条件是否分别记录。

## 7. 如何核验每次输出

不要只看回答是否顺畅。至少检查以下四点：

1. **来源是否清楚：** 哪些来自指南，哪些来自你提供的材料，哪些是 AI 建议或推测？需要时要求指出包内文件和相应段落。
2. **事实是否成立：** 金额、期限、角色、字段、权限和客户确认，是否真的有证据？没有证据就保留为未知。
3. **操作是否发生：** 草稿不等于已发送，代码不等于已运行，建议验收不等于客户已签字。执行结果要看日志、测试结果或目标系统实际状态。
4. **边界是否守住：** 是否只使用本项目材料，是否越过授权，是否把别的项目条件搬过来？发现不一致时先纠正事实，再继续。

涉及法律、财税、安全或正式商业承诺时，请交有资格的专业人员及有权负责人核验。AI 的评审意见不是组织授权。

## 8. 升级、旧版兼容与回滚

仓库保留的 `skills/zhxbai-fde` 是旧版 0.4.2，其内部 `name: zhxbai-fde` 保持不变。这是保留旧版供兼容和回看，**不是新名称的自动别名**。调用 `$zhxbai-fde` 不等于调用 `$zhixiong-fde-expert`，不要同时安装两个总包。

本版0.4.4修正对话式追问：每轮只问一个独立未知，不以一个问号合并多个可分别回答的问题；用户明确要求会议提纲或核对清单时仍可列多个问题。`SKILL.md`、`PROVENANCE.json`、`RELEASE.json.version`、`references/registry.json.version` 与 `RELEASE.json.method_baseline_version` 均记录0.4.4。历史旧总包0.4.2及18个独立发行包不变；其中chat独立发行包不因源码chat版本更新而自动升级。版本不是能力认证或宿主验证标记。发布前验证范围与限制见0.4.4验证记录；实际公开发布状态以仓库提交为准。

升级建议：

1. 先看[检查与版本记录](https://github.com/zhixiongbai960-design/zhixiong-fde-guide/blob/main/skill-source/docs/检查与版本记录.md)和对应提交，确认你要安装的版本。
2. 保存自己的项目记录。项目文件不要放进公共技能目录，以免升级时混淆。
3. 将当前总包整个移到**技能安装目录之外**，标注版本留作备份。只在同一技能目录内改名，仍可能被宿主扫描，不算卸载。
4. 按安装步骤复制新包，开启新会话并复查版本和资料读取。不要合并覆盖文件夹，以免留下旧文件。
5. 如需回滚，先将新包移出技能目录，再把备份包放回原位置，开启新会话。回到旧总包 0.4.2 时，调用名也应恢复为 `$zhxbai-fde`。

已经安装的包是固定快照，不会因为仓库更新或作者修改方法而静默变化。升级需要你获取并安装新版本。
