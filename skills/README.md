# FDE 课程方法与 Skills

**志亚科技出品 · 作者：白志雄**

将课程方法变成学员可理解的方法卡，以及可直接引导实操的 Skill。面向 Datawhale FDE 训练营的 3+3+1 结构：前三天个人MVP，第4–6天递进真实案例，第7天展示与复盘。

## 使用顺序

fde-ready（环境）→ fde-knowledge（材料）→ 既有需求追问挖掘 → fde-review（判断）→ fde-scope（范围）→ 既有需求技能生成MVP规格 → fde-design（设计）→ fde-build（构建）→ fde-deliver（验证交付）。讲师使用 fde-case 准备后续真实案例。

已完成且证据充分的步骤直接复用，禁止重复问卷。所有方法在同一份项目记录增量更新。直接使用某个Skill也不必强制走完整链路。

## 技能目录

| 名称 | 做什么 | 输入 → 输出 |
|---|---|---|
| fde-ready | 课前四步就绪 | 指定环境和示例 → 实测状态或阻塞 |
| fde-knowledge | 当前任务知识整理 | 已授权材料和任务 → 最小索引、出处和缺口 |
| fde-review | 需求判断 | 已整理需求 → 阶段判断、证据、补问/下一步 |
| fde-scope | 机会、范围与变更 | 候选需求/变更 → 取舍、范围、责任与确认项 |
| fde-design | 最小方案设计 | 已确认MVP规格 → 流程、分工、字段、验证方案 |
| fde-build | 业务Skill构建 | 方案和方法 → 技能源文件、配置、样例与验证状态 |
| fde-deliver | 验证、交付、复盘 | 需求和运行证据 → 验收、交接、迁移和按需路演 |
| fde-case | 案例教学设计 | 讲师真实案例 → 教学版、预演与独立变化任务 |

既有[需求追问与挖掘](https://github.com/zhixiongbai960-design/requirement-analysis)保留英文入口 requirement-analysis，目前核实版本2.1.0；它负责从模糊场景追问、形成需求、回写评审及本人确认后的MVP规格。不要把它改成重复审核问卷。本目录不复制其实现，不改变其许可证。

## 启用和边界

每个技能目录包含标准SKILL.md。按宿主支持的方法导入对应目录；本次发布不等于已安装到你的Agent。宿主不支持跨技能调用时，切换技能并传入上一份产物。没有调用证据就不能声称自动链路跑通。

先阅读方法卡，再选择当前环节的技能。学员仍须决定业务目标、确认范围、亲自修改规则和核对结果。Skills不替代讲师、真实用户或生产安全审查。

本套件来源于课程共同方法，新增细化为共创建议。第四至六天行业案例由对应讲师提供，本套件不虚构真实案例。接口、存储和外部发送按需且按授权执行，不要求为完成架构图堆工具。生产稳定、采用意愿和商业收益分别验证。
