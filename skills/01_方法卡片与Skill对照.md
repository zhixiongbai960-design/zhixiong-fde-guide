# Datawhale FDE 训练营｜方法卡片与 Skill 对照

版本：共创初稿 0.1｜2026-11-09

课堂讲方法，让学员知道为什么这样判断；实操用 Skill，让方法成为行动。卡片是人的理解抓手，Skill 是引导和执行规则，不替学员做业务决定，也不把 AI 评审替代讲师/真实用户验证。

## 使用安排

按现有八模块和 3+3+1 结构复用，不新增一套课程。15 张方法卡对应现有需求追问挖掘和8个新Skill源文件；不要求学员背12张卡或安装15个重复技能。第4–6天用同一套方法处理讲师真实案例，不预造讲师案例。

推荐学员仅安装总技能 zhxbai-fde，以下垂直名称表示包内方法分工，也可按需独立安装。

默认课堂链路：项目知识整理 → 需求分析 → 需求判断（补关键缺口）→ 本人/讲师评审与范围确认 → 现有需求分析生成MVP规格 → 最小方案设计 → 业务Skill构建 → 验证交付与复盘。

已有需求分析的课堂评审/规格流程仍可单独使用。需求判断是独立复核入口，也可日后作为其内部模块集成；本轮不覆盖已安装稳定版。总技能直接读取包内对应方法，不需要跨Skill调用；单独选用垂直技能时，按宿主能力切换并传入上一份产物。

## 01 任务材料最小集

- 课程位置：第1天1.1–1.3｜模块01
- 对应 Skill：zhxbai-fde-knowledge
- 带走的公式：**当前任务 → 需要什么判断 → 哪些资料能支持 → 缺什么**
- 怎么做：只选一个候选任务，把笔记、样例、规则和案例登记来源/日期/适用范围；用一个真实问题查一次。
- 得到什么：材料索引 + 一次带出处回答；找不到的明确标未知。
- 容易错在哪：拿“材料数量多”代替“任务可用”；把来源明确当作内容永远正确。
- 实操启动语：用这些材料帮助我处理这个任务，只整理必要部分，并用一个真实问题检查能否调用。

## 02 一次真实任务走查

- 课程位置：第1天1.6｜模块02
- 对应 Skill：requirement-analysis（已有）
- 带走的公式：**触发 → 输入 → 动作/判断 → 输出 → 用途**
- 怎么做：回忆最近一次真实经历，沿实际做法说，不照制度或理想流程编；追问在哪一步停下或返工。
- 得到什么：实际流程、具体卡点、支持它的例子和未知。
- 容易错在哪：先推荐工具；把效率低直接当根因。
- 实操启动语：请从我最近一次处理这件事的经过开始，一轮问一个问题，帮我找到具体卡点。

## 03 As-is / To-be 与目的

- 课程位置：第1天1.6｜模块02
- 对应 Skill：requirement-analysis（已有）
- 带走的公式：**当前怎么做 → 想到什么状态 → 差距在哪里**
- 怎么做：分开目的与候选方法，核对结果被谁用于什么行动；不强迫推翻已清楚的小需求。
- 得到什么：现状、目标、影响及最小改善方向。
- 容易错在哪：把买工具、做App、赚钱等方法当成唯一需求；强行发明更深动机。
- 实操启动语：帮我分清现状、目的和解决办法，保留我已经明确的条件。

## 04 需求三问与证据

- 课程位置：第1天1.6–1.7｜模块02、03
- 对应 Skill：分析由 requirement-analysis；复核由 zhxbai-fde-review
- 带走的公式：**为了目标遇到什么问题？→ 卡在哪一步？→ 凭什么认定是这里？**
- 怎么做：沿一个真实样例检查；原因无依据时保留假设，多处制约不强求唯一根因。
- 得到什么：目标—问题—卡点—依据—未知的需求链。
- 容易错在哪：连续追问为什么却不看事实；把本人确认当作根因已被证实。
- 实操启动语：检查我的目标、问题、卡点是否连得上，只追问最影响判断的一个缺口。

## 05 需求判断与推进门槛

- 课程位置：第1天1.7–1.8｜模块03
- 对应 Skill：zhxbai-fde-review
- 带走的公式：**场景/问题/目的 → 依据/范围/验证条件 → 反馈或推进**
- 怎么做：核对六组维度；完整则进入范围确认与规格，缺失则具体反馈、一次补一问。
- 得到什么：可讨论 / 可做有限验证 / 暂不实施，以及依据和下一步。
- 容易错在哪：把表填全叫真实需求已证实；没有商业预算就判伪需求。
- 实操启动语：评审这份已整理的需求，沿用已知信息，告诉我缺什么及为什么；清楚就继续，不重做问卷。

## 06 MVP 切小与规格交接

- 课程位置：第1天1.8；第2天2.1｜模块03、04
- 对应 Skill：requirement-analysis（已有规格）；zhxbai-fde-design 接设计
- 带走的公式：**一个主要使用者 + 一个核心任务 + 一条主要流程 + 一个可核对结果**
- 怎么做：列本轮包含/不包含/人工处理；确认输入和输出用途；本人确认范围后形成规格，缺口显式标注。
- 得到什么：同一份持续更新的 MVP 需求规格，不另做重复版本。
- 容易错在哪：把最小理解为只做零碎功能；默认加登录、数据库或自动发送。
- 实操启动语：在已确认需求里切出最小完整结果，确认范围后整理MVP规格，标出开工阻塞。

## 07 最小架构与责任分工

- 课程位置：第2天2.2–2.4；第4–6天｜模块04
- 对应 Skill：zhxbai-fde-design
- 带走的公式：**任务组织 → 方法规则 → 确定性执行 → 资料/状态 → 人负责**
- 怎么做：逐步说明谁做、输入输出和失效怎么办；先基础路径，按业务必要性加外部能力。
- 得到什么：最小流程/架构关系、组件取舍、数据与人工责任。
- 容易错在哪：先凑三层图再找需求；把Skill说成独立执行引擎。
- 实操启动语：根据这份规格设计最小方案，解释哪些只需Agent和Skill，哪些确实需要代码、API或存储。

## 08 上下文与方法配置分离

- 课程位置：第2天2.5–2.6｜模块05
- 对应 Skill：zhxbai-fde-design + zhxbai-fde-build
- 带走的公式：**长期规则 / 当前任务 / 相关材料 / 工具输出；通用方法 ≠ 客户配置**
- 怎么做：只给当前步骤所需信息，标版本和来源；字段、阈值、路径等另列配置，凭据不写入共享技能。
- 得到什么：可复用方法、可替换配置、必要上下文。
- 容易错在哪：把所有资料塞进上下文；把客户字段和秘密硬编码进方法。
- 实操启动语：把这套方法封装时，分开通用步骤和项目配置，并说明每一步需要哪些材料。

## 09 业务 Skill 六件事

- 课程位置：第2天2.6–2.8｜模块05
- 对应 Skill：zhxbai-fde-build
- 带走的公式：**适用场景 + 输入 + 步骤 + 判断规则 + 输出 + 异常停止**
- 怎么做：先复用可用技能，再写最小版本；本人改一条规则、预测变化、用样例核对。
- 得到什么：业务SKILL.md、必要配置与样例、首跑状态。
- 容易错在哪：只有专家角色提示；AI替学员全部完成后声称独立掌握。
- 实操启动语：把已确认方法做成Skill，给出正常和异常样例，保留需要我亲自修改的一条规则。

## 10 证据链与分层排错

- 课程位置：第2天2.8；第3天3.1–3.3；第4–6天｜模块05、06
- 对应 Skill：zhxbai-fde-deliver
- 带走的公式：**预期 → 实际 → 差距 → 最小复现 → 修正一处 → 回归**
- 怎么做：沿需求、规则、材料、工具连接、配置环境定位；核对原始返回/最终记录，不只看模型解释。
- 得到什么：失败证据、定位理由、修正记录与复测结果。
- 容易错在哪：全部归因提示词；只保留成功截图；未运行写通过。
- 实操启动语：根据这个真实错误和输入，定位问题在哪一层，给出最小修正并区分已测和未测。

## 11 停止、接管与可复跑验收

- 课程位置：第3天3.2–3.6｜模块06、07
- 对应 Skill：zhxbai-fde-deliver
- 带走的公式：**正常 + 相关异常 + 换输入/改规则 + 重启 + 同伴试用**
- 怎么做：明确何时补问/停、交给谁、带哪些记录；重复失败受预算限制，外部写入结果不明先查状态。
- 得到什么：注明版本的验收证据、最小运行说明、未测与责任边界。
- 容易错在哪：无限重试；把模拟调用算真实调用；把小样本成功称生产稳定。
- 实操启动语：按我的需求和运行证据做最小验收，检查失败是否会停、别人能否按说明复跑；缺证据就列未验证。

## 12 复盘迁移与有证据路演

- 课程位置：第3天3.7–3.8；第4–7天｜模块08、01
- 对应 Skill：zhxbai-fde-deliver
- 带走的公式：**原判断 → 实际观察 → 改变 → 适用条件 → 下一次验证**
- 怎么做：比较案例与个人项目，选一项有用方法迁回或解释不增加复杂度；路演讲价值与证据，不堆功能。
- 得到什么：一次复盘、技能更新建议、路演事实/限制、下轮验证。
- 容易错在哪：把未经测量的收益当成果；把最终电梯演讲模板套回早期需求初评。
- 实操启动语：整理这次项目的实际结果和限制，告诉我可复用什么，并准备一个有证据的项目叙事。

## 边界与后续

方法卡是流程记忆和操作支架，不是被证明适用所有业务的科学定律。推进门槛依当前任务和风险判断，不以填满模板或总分决定。

本套件不修改课程主体或已安装需求分析。GitHub发布不等于宿主安装或实测。尚需在最终统一教学宿主中检查加载、触发和多轮行为。实际业务写入/发送、共享、安装和凭据配置仍遵循用户授权。

## 13 机会、范围与变更

- 课程位置：第1天1.4、1.5、1.8及后续案例｜模块02、03、07。
- 对应Skill：zhxbai-fde-scope。
- 公式：影响与紧迫性 × 可验证条件 × 投入约束 → 继续/补条件/缩小/暂停。这里是组合判断，不是要求数值相乘。
- 怎么做：比较候选的真实影响、材料和反馈、授权、依赖与时间；明确包含/排除/人工处理。变更沿“原范围→新请求→影响→取舍→确认”处理。
- 产物：机会判断与最小范围、责任/验收/维护边界。
- 易错：低频就判伪需求，未经确认承诺报价/工期，忽略变更连带影响。
- 启动语：帮我比较这些候选在本轮适不适合做，指出依据、未知和最小验证范围，不替我承诺客户。

## 14 课前四步就绪

- 课程位置：课前准备｜模块05、06的环境前提，不提前转移核心教学。
- 对应Skill：zhxbai-fde-ready。
- 公式：打开材料 → 运行示例 → 找到输出 → 改输入重跑。
- 怎么做：逐步记录本人操作和实际证据，故障定向辅导，必要时使用已批准备用环境。
- 产物：四步就绪记录、阻塞与支持安排。
- 易错：装好软件就算通过；同伴代做算本人掌握；把编程能力变临时门槛。
- 启动语：按照统一教学环境帮我检查这四步，只记实际做成的，没做的标清楚。

## 15 真实案例教学准入

- 课程位置：第4–6天案例共创及课前准备｜贯穿八模块。
- 对应Skill：zhxbai-fde-case。
- 公式：一个主要新增复杂度 + 完整闭环 + 非作者限时预演 + 一项独立变化。
- 怎么做：讲师补真实案例，标课堂简化；非原开发者预演配置、讲解、练习、测试、交接耗时，超时缩小而不挤掉测试。
- 产物：案例卡、预演记录、独立变化任务和准入待决项。
- 易错：用主讲者独自跑通代替可教性；编造案例；把复制成品算独立迁移。
- 启动语：把我这个真实项目切为当天教学案例，指出新增理论、必要约束与预演办法，没预演不要写通过。
