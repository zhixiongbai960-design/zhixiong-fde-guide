# MVP 需求规格模板

使用已确认需求填写；未知、建议、待验证必须明确标记，不用占位模板冒充已完成文档。默认中文，随用户语言调整。简单任务可以合并章节，但不能遗漏影响开工和验收的信息。

```markdown
# MVP 需求规格：<名称>
版本：<版本>｜日期：<实际日期>
状态：待确认草稿 / 本人已确认范围的规格；实施可行性尚未验证
依据：<本轮需求描述及本人确认的范围；评审意见及状态>
## 1. 场景、问题与目的
- 谁在什么场景，需要解决什么问题，期待什么业务结果。
- 卡点与依据；仍未证实的原因。
## 2. 最小范围
- 本版包含：<只保留达到目标所需内容>
- 本版不包含：<明确排除项>
- 建议/待确认：<不能混入已确认范围>
## 3. 输入、处理、输出与使用
- 输入：来源、样例/格式、必要字段、可用性；缺失如何处理。
- 主流程：输入 → 必要动作/判断 → 输出 → 人核对 → 实际用途。
- 输出：内容/格式、接收者、用途。
- 人工负责：核对、关键决策、异常接管。
## 4. 功能与需求对应
| 功能 | 对应问题/目的 | 输入与规则 | 输出 | 是否本版 |
|---|---|---|---|---|
| <实际填写> | <需求依据> | <已知规则或待确认> | <结果> | <确认状态> |
## 5. 实现边界与数据
- 最小候选方案与确认状态；Agent执行，Skill提供方法。
- 工具/接口：仅列已知或候选；权限与连通性标验证状态。
- 是否需要持久存储；需要时写数据项、读写动作、来源及授权边界。
- 不需要的组件明确不引入。不得在此保存凭据。
## 6. 验收与试跑
| 场景 | 输入/前提 | 预期结果 | 谁怎样核对 | 实际状态 |
|---|---|---|---|---|
| 正常样例 | <已有或待准备> | <可观察结果> | <人工/规则> | 未运行 |
| 关键缺失/失败 | <最相关异常> | <停止/提示/人工接管> | <核对方式> | 未运行 |
- 哪些结果是预期而非已验证；没有量化标准时用可观察现象。
## 7. 待确认与开工条件
- 已确认：<有对话依据的事实、范围>
- 待确认：<不阻断当前小范围的未知>
- 开工前阻塞：<会改变核心输入、输出、权限或方案的缺口>
- 下一步：<文档确认/补材料/授权/试跑；不默认已执行>
```
