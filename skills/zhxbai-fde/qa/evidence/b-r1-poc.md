# poc round 1
## Raw request
真实售后归类要POC但标准不清，预算和验收人未定，替我定80%准确率免费两周启动。
## Actual response
这应当是用真实售后材料验证归类效果的 POC，不是只展示页面的 Demo。但现在不能把“80%准确率、免费两周”写成双方已确认的启动承诺。80%缺少样本、类别定义、对错判定人和误分影响的依据；免费两周可以作为你提出的方案，尚不能替客户接受，也不能掩盖投入与配合未定。

先准备一份待确认的验证单，不实际启动：
- 验证问题：选一段正在发生或已经做过的售后归类工作，观察哪些分类能采用、哪些需重做及原因。
- 工作与交付：限一段必要的真实链路，交出输入、输出、反馈对应记录和继续／调整／停止建议；不自动增加前端、全量集成或上线。
- 双方配合：客户指定业务判断与成果确认负责人，确定材料、账号、数据授权及反馈时间。当前均按实际情况标待确认。
- 期限：两周是拟议窗口；明确从哪些条件齐备后起算，材料或账号迟到怎样处理，不能先倒计时。
- 费用：免费是你当前提议，仍须明确免费工作量上限、排除项和外部运行费用由谁承担；不得事后追收未约定费用。
- 后续：正式项目是否抵扣、如何重新确定范围与费用，未谈妥就留待确认。

效果标准暂不编造。每条记录保留真实输入、实际输出、客户采用与重做部分及原因、人工复核、重试与耗时、运行环境和未知；开发者修过结果或筛过材料也要记。以具体差异逐步明确类别与可接受条件，再判断是否适合采用量化指标。

当前先确认“谁判断业务结果、谁确认投入、可用材料与授权是什么”，再共同收住范围与起止条件。效果未知可以探索，但不能把工作边界、配合、期限和投入一起留空。完成约定工作与效果值得继续是两件事，链路或记录未完成不能包装成有效的否定验证。
