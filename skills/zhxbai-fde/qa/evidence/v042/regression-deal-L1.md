# 当前题面 L1

换一个已签小试点合同：只交付本地会议候选行动项提取，不接业务系统；我已收3000元启动款，余3000元客户书面验收后付。客户今天说“顺便自动把任务写进飞书吧，我微信回了收到，预算不加”。请帮我判断是否原义务、该怎样更新范围和沟通，不要发消息、不要改系统。

# 逐字答案

按你提供的合同范围，自动向飞书写任务属于范围外的新增能力，应列为变更候选，不是本地候选行动项提取的原义务。是否额外收费另行判断，可以评估后主动吸收，但“预算不加”本身不能证明双方已同意免费扩展。“收到”也不足以据此认定你接受了新增范围和零加价；仍应核对微信完整上下文及合同变更条款，不在这里判断法律效力。

建议这样更新记录和推进：
- 已确认范围：本地会议候选行动项提取，不接业务系统。已收启动款3,000元；尾款3,000元仍按客户书面验收后支付，不因这次请求自行改付款条件。
- 客户请求：自动将任务写入飞书、预算不增加。单列为待评估变更，不直接写进已确认交付或原验收标准。
- 先评估影响：确认写入飞书的具体功能及目标位置、候选项是否需人工确认、任务字段和负责人映射、接口与权限、数据传输边界、失败重试与重复任务处理，以及新增测试、客户配合、部署维护和交期影响。以上目前未核实，不能假定“顺便”就能完成，也不能承诺原交期不受影响。
- 给有权负责人选择：维持原范围、飞书接入另期处理；或评估后在明确边界内本期免费吸收；或双方同意替换部分范围；或增加预算／调整交期。预算不加时尤其要说明可承担的范围及时间，不默认免费无限扩展，也不擅自削减原交付。
- 选定后再留书面确认：记录范围版本、包含与排除、费用是否变化、交期、客户配合、测试和验收标准，以及是否影响尾款触发条件。同步范围、计划和验收依据，再按授权实施；原功能仍需验证，新增写入需有测试及必要回退安排。未确认新增前继续履行原合同，不擅自停掉原服务。

可用的沟通草稿（未发送）：
“飞书自动写任务的需求我已收到。原试点约定是本地会议候选行动项提取，不含业务系统接入；这次飞书写入需要单独评估接口权限、任务规则、测试及交期影响，我此前回复‘收到’是确认收到需求，并非确认免费纳入。理解您希望预算不增加，我们可以先按原范围完成试点，把飞书接入放到后续；也可以评估是否能在明确边界内吸收，或协商范围与交期调整。具体采用哪种安排，待双方有权负责人书面确认后再执行。当前已收启动款3,000元，余款3,000元仍按合同在您书面验收后支付。”
