## 公开角色与来源

总技能提供名为“志雄”的FDE项目实战AI助手角色，不是白志雄本人，不默认代表本人观点或授权。普通任务直接答复，不要求每轮自我介绍或输出来源标记。各分发包的PROVENANCE.json仅记录zhxbai、作者、来源、版本和许可位置；不执行、不联网、不追踪、不改变历史许可。明文标识可以被删除，不能当防复制或不可篡改保护。

## 给使用者

每个 zhxbai-fde-* 小技能是独立包，带自己的方法、必需模板、指南原文和许可，不需要安装其他小技能。新总技能 [zhixiong-fde-Expert](../skills/zhixiong-fde-expert/)（安装名 `zhixiong-fde-expert`）是这些通过测试模块的固定快照，一次安装覆盖全流程。[使用说明书](docs/专家技能使用说明.md)讲解安装、升级和边界。旧 `zhxbai-fde` 0.4.2保留不动，不是自动别名。总包和小包均不依赖第三方SkillHub脚本。

## 给维护者

唯一权威方法在 src/methods/，名称/描述/资料依赖在 src/registry.json。src/guide/保留用户指南完整文字；src/total-SKILL.md维护总入口角色与行为，project-navigation.md负责问题路由。

请修改权威源，不直接手改已生成的dist或GitHub分发目录。小模块改动不即时改变已安装总包；通过受影响模块回归后重新构建，才产生新的总包快照。旧总包在替换前继续原样使用，不宣称自动更新。

## 方法维护流程

1. 改一个模块或其确有必要的引用资料；保留来源与许可。
2. 运行 python3 tools/package.py affected --module need 等命令查看受影响依赖，运行hashes取得当前指纹。源码变化使对应证据过期，不能沿用旧通过。
3. 若发布独立包，运行build-modules；若像0.4.4只发布专家包，则用Packager.module生成受影响模块到仅测试暂存目录，不覆盖冻结的skills独立包。逐个做正常/异常/衔接行为测试；每个受影响模块至少两轮实际响应和独立审查。测试证据保存在qa/evidence，确认真实结论后记录qa/modules.json。
4. 对需要发布的产物检查字节与来源。0.4.4仅在QA与当前指纹一致后运行package_expert.py build和verify；不构建或覆盖旧总包、18个历史独立包。构建程序检查证据文件/版本关联，不能替代对证据含义的人工审阅，不得为了过关伪造pass文件。
5. 构建后再用总入口做跨模块回归，核对生成包、许可、链接和来源。GitHub发布/用户安装是独立步骤，不因本地构建自动发生。
6. 失败时保留上一次成功产物，不用半成品覆盖；需要退回可运行rollback --target total或modules。保留一份上一版本。运行构建/回滚时不并发读取/安装正在切换的目录。

工具只使用Python标准库。路径限制、拒绝越界/符号链接、依赖循环/缺文件、失败保留旧产物、QA过期和低耦合影响等已做自动化测试。文件切换有短暂重命名窗口，不宣称掉电完全事务性或生产部署系统。

## 回归范围

- 改need方法：影响need以及review/scope等依赖者；不影响与它无关的方法。
- 改总导航或总入口：不使所有独立方法重新失效，但必须重测总包路由。
- 改共享许可或构建器：影响所有相关分发包，需重新验证包装与绑定。
- 改某篇指南：重查使用该篇的模块及其实际受影响行为，不机械全量加载33篇。

真实宿主/业务系统验证与离线方法响应不同。本版本未进行WorkBuddy等目标宿主安装验证，报告不把离线方法响应或合成代码测试写成宿主或生产验证。
