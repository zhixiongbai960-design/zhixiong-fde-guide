实现时最好由一个公共响应构造器产生输出，并在最外层异常处理处也调用它，避免某个分支漏字段。若旧 id 是业务记录 ID，而非请求关联 ID，不能直接改名为 request_id；应单独生成请求 ID，业务 ID 仅在有必要且允许返回时放进 data。同样，旧 source 必须核实确实是采用的规则来源，不能只改键名就算完成。

### 2. 建议采用这份统一契约

所有由 Skill 控制的结构化响应都包含同一组字段：

| 字段 | 类型与约定 |
|---|---|
| request_id | string 或 null。优先使用入口生成的安全关联 ID；若接收调用方 ID，先校验长度、字符集和格式。无效时生成新的 ID，不回显原始内容。确实无法取得时明确为 null。 |
| status | 本次建议先限定为 NEEDS_REVIEW 或 FAILED。NEEDS_REVIEW 表示流程产生了“需人工复核”的业务结果，不表示金额正确、审核通过或允许付款。其他业务状态须先按已确认规则补定义。 |
| rule_source | object 或 null。对象至少含 rule_id、version，使用不泄露客户信息的规则标识。只返回已确认、实际采用的来源；失败发生在规则加载前时为 null，不伪造来源。 |
| data | 成功时为业务结果对象，失败时为 null。实际金额结果字段另按已确认业务规格定义。 |
| error | 成功时为 null；失败时为包含 code、message 的对象。错误文案经过脱敏，不返回堆栈、token、手机号、私有表地址或未经校验的原始输入。 |

补充两个约束：

- 所有键都存在，不等于所有值都必须非空。request_id/rule_source 的 null 条件必须在文档和测试中一致。身份认证信息、真实表 ID 都不能拿来充当追踪字段。
- “所有输出”改写为“所有由 Skill 控制的结构化响应”。宿主启动失败或进程被终止可能没有应用响应，需由调用方识别超时或无响应，不能承诺 Skill 总能包装这类故障。

下面都是合成示例，规则标识和请求 ID 不对应真实客户，也不替你设定金额阈值。

成功，产生“需人工复核”的结果：

```json
{
  "request_id": "req_demo_001",
  "status": "NEEDS_REVIEW",
  "rule_source": {
    "rule_id": "amount-review-demo",
    "version": "example-v1"
  },
  "data": {
    "review_required": true
  },
  "error": null
}
```

失败，缺少必要输入，尚未加载规则：

```json
{
  "request_id": "req_demo_002",
  "status": "FAILED",
  "rule_source": null,
  "data": null,
  "error": {
    "code": "INPUT_MISSING",
    "message": "缺少必要的金额字段，请补充后重试。"
  }
}
```

失败，已确认规则，但只读查询接口超时：

```json
{
  "request_id": "req_demo_003",
  "status": "FAILED",
  "rule_source": {
    "rule_id": "amount-review-demo",
    "version": "example-v1"
  },
  "data": null,
  "error": {
    "code": "DEPENDENCY_TIMEOUT",
    "message": "金额查询未完成，请人工核查后决定是否重试。"
  }
}
```

三种输出都保留相同的顶层结构。失败也保留能安全取得的关联 ID 和规则来源；取不到就明确 null，而不是只剩一个 error。若外部操作存在写入且超时后结果不明，应先核验实际结果，不要自动重放。

### 3. 主文档、配置及实现分别改什么

**SKILL.md：**

- 保留可解析的 name、description frontmatter，名称与目录使用小写连字符。
- 写清触发范围、必需输入、金额字段含义、币种、规则来源、复核步骤、输出契约和停止条件。
- 缺关键金额、规则缺失或冲突时停止并说明缺口；不要凭模型补规则、借用上个客户的配置或默认继续。
- 写清工具失败的重试上限和人工接管角色。交接仅含安全请求 ID、错误码、已确认规则版本及需要补充的信息。
- 将“尚未实测”“未安装”等本次交付状态放 README 或验证记录，不写成 Skill 永久禁止运行的规则。

**配置说明及公开样例：**

- 按实际需要列出逻辑配置项，例如目标表、金额字段映射、规则版本、阈值及接口地址。配置说明记录来源、负责人/确认状态，不含真实客户值。
- 公开样例用完全合成的表标识和数据；手机号如果非复核必需，直接去掉，不为演示而保留。
- token 通过宿主支持的安全配置或秘密管理方式注入。环境变量只是可选机制，必须确认实现确实支持，不在文档里虚构能力。
- 不只看主文档：公开前检查示例、截图、日志、测试夹具、构建产物及拟公开的版本历史。忽略规则不能清除已经跟踪或写入历史的秘密。
- 如果 token 曾经进入可被他人访问的材料，应按泄露处置并轮换；这里没有证据表明已经泄露，不能直接下结论。本次不替你执行轮换或历史改写。

**实现：**

- 把金额解析、字段映射和规则判定落到可重复验证的代码。根据确认的业务规格使用十进制定点或最小货币单位，明确舍入时机，不能依赖模型心算或二进制浮点碰巧相等。
- 集中校验输出 schema，保证早期返回及异常处理与正常路径一致。
- 规则来源从实际加载的配置取得，并与当前请求绑定，不能硬编码成演示来源。
- 将错误映射为稳定错误码；对授权失败、规则缺失、配置错误和查询超时分别处理。敏感原始错误不得直接拼入返回值或普通日志。
