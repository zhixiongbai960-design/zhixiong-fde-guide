# MVP需求规格：本地工单候选ID筛选

版本：v1.0｜日期：2026-11-09  
状态：本人已确认范围的规格；技术可行性及实际效果尚未验证。没有已提供的讲师评审结论。

## 1. 场景、问题与目的

你每天从本地CSV中找出high且open的工单ticket_id，供本人核对。现在手工筛选容易漏，希望把固定规则的筛选过程变成可重复、可核对的小任务。人工复核继续保留。

“容易漏”来自你的自述；具体发生频率、原因和改进幅度尚未实测，不在本规格中编造收益指标。

## 2. 最小范围

本版包含：读取一份本地CSV，全文件校验，通过后筛选severity精确等于high且status精确等于open的记录，仅在终端显示其ticket_id；没有匹配记录则显示“零条”。

本版不包含：上传、联网模型处理、自动发信或发主管、CRM读写、重新判级、自动修复或补全字段、导出结果文件、数据库、登录、多角色界面及定时任务。每天使用是场景，不等于已经要求自动调度。

## 3. 输入、处理、输出与人工职责

**输入与规则**

- 来源：用户本地CSV；UTF-8编码、逗号分隔。
- 必需列：ticket_id、severity、status。
- ticket_id：必需非空，且在全文件内唯一；重复判断不能只检查最终命中的行。
- severity：仅允许high、medium、low。
- status：仅允许open、closed。
- 所有匹配按原值精确比较，不trim、不自动改大小写、不把非法值改成看起来合理的值。
- 缺必需列、必需值为空、非法枚举、重复ticket_id或CSV解析错误，均使整份文件失败，不产生任何候选ID。
- 字符串空值与空格不能偷偷混为一谈：空字符串属于空值；high前后有空格不合法。纯空白ticket_id若要额外禁止，需要明定规则，不能通过偷偷trim实现。

**主流程**

选择本地文件 → 只读解析并完成全文件校验 → 全部通过后筛选两个条件同时成立的记录 → 终端显示ID或“零条” → 你本人核对。

必须先完成全文件校验，再释放候选结果。即使前几行已经命中，后面出现错误也不能留下部分候选。

**输出与人工接管**

- 成功：只显示命中的ticket_id；无命中显示“零条”。不附带工单其他内容，不生成结果文件。
- 失败：停止且无候选，不能把失败伪装成成功的“零条”。错误提示的最小格式和输出通道在方案设计中明确。
- 你负责核对候选、处理源文件错误以及决定后续业务动作。程序不代替你修改CSV或更新工单。
