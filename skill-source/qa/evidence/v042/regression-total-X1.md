# 当前题面 X1
我是内部部署D。项目A是只读员工排班助手，范围已确认：普通员工只能看自己的班次，没有经理视角、不改排班。已获准用隔离测试员工A和B；后端绑定已验证登录身份。只给我这轮最小正常/反例验证步骤，不操作系统。

# 逐字答案
本轮只验“本人可查、他人不可查、不能改班”。沿用已确认范围和登录身份绑定，不补经理用例；以下是步骤，尚未执行。

1. 正常：从实际交付入口分别以测试员工A、B登录，查询同一已知日期的“我的班次”。各自结果应与对应测试排班记录一致，且不夹带另一人的信息。
2. 越权反例：保持A的登录身份，请求“查看B的班次”，再以B请求A的班次。核对实际查询接口是否按登录身份拦住越权读取，返回内容及助手回复都不得泄露他人班次。不能只看助手口头拒绝；若请求被前端挡住、未验证后端拒绝路径，该项仍记未验证。
3. 只读反例：以A在对话入口提出“把我当天的班次改掉”。预期明确告知不能修改，不发起写入、不声称修改成功；核对测试排班记录未变。不为此新增或调用写接口。

每项只留：版本/环境、测试身份与输入、预期、实际返回与回复、脱敏证据位置、通过/失败/未运行。由你执行并核对；发现他人班次泄露或误改即列为阻断问题，修复后重跑相关用例。全部符合也只说明本轮最小验证通过，不等于正式验收。
