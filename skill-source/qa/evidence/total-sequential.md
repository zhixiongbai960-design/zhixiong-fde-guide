# MVP 需求规格：本地工单双条件筛选
版本：v0.1｜日期：2026-11-09
状态：本人已确认范围的规格整理；本文尚未逐项复核，实施可行性未验证。

## 1. 场景、问题与目的

你每天从本地 CSV 找出符合条件的工单，自己核对后处理。

当前卡点是手动筛完一个条件后，容易忘记叠加另一个条件。依据是你本轮的明确说明，尚无实际文件或运行观察。目标是把两个条件作为不可拆开的筛选规则，减少对手动步骤记忆的依赖，不替代你的业务核对与处理。

## 2. 最小范围

本版包含：
- 读取指定的本地 UTF-8、逗号分隔 CSV。
- 对整份文件进行必要校验。
- 仅在全文件校验通过后，筛出同时满足两个条件的工单。
- 仅在终端显示符合条件的 ticket_ref；成功且没有匹配记录时显示“零条”。

本版不包含：
- 上传文件或结果、调用外部模型处理业务数据。
- 发信、修改 CRM、自动处理工单。
- 修改原文件、输出结果文件、数据库、后台服务或定时任务。

## 3. 输入、处理、输出与使用

必需列及规则：
- ticket_ref：非空，在整份文件中唯一。
- priority_code：合法值仅为 H、M、L。
- state_code：合法值仅为 O、C。
- 按解析后的值精确匹配，不 trim，不自动改大小写或纠正非法值。

主流程：
1. 读取本地 CSV。
2. 校验解析结果、必需列、必需值、合法编码和 ticket_ref 唯一性。
3. 任何位置出现缺列、空值、非法值、重复或解析错误，整份文件失败，不产生任何候选。即使前面已有合格行，也不能先输出。
4. 全部校验通过后，使用同一个条件筛选：priority_code 等于 H，且 state_code 等于 O。
5. 终端只呈现入选的 ticket_ref，或成功无匹配时的“零条”。
6. 你核对结果后自行处理工单。

异常由你接管，检查并修正输入后再决定是否重试；工具不擅自跳过坏行、补值、去重或替你修文件。失败不能伪装成成功的“零条”。

## 4. 功能与需求对应

- 整文件校验：对应“缺列/空/非法/重复/解析错误全文件停止无候选”。
- H 与 O 联合筛选：对应“筛完 high 后忘了再筛 open”的操作卡点。
- 延迟输出：保证文件后部出错时，不会留下前面已打印的候选。
- 终端结果：对应“只终端显示 ID 或零条”，供你复核。
- 保留人工处理：对应“自己核对后处理”，不扩大为业务写入。

## 5. 实现边界与数据

建议的最小方案是本地确定性筛选工具，具体语言、启动方式和实现结构留到方案设计选择。筛选本身不需要模型逐行判断，也不需要在线 API 或新增数据存储。

只在本机的限制同时覆盖文件、处理过程、日志、工具回传和模型上下文。真实 CSV、ticket_ref 和其他业务值不得因调试或调用 AI 而外传。本轮没有读取真实 CSV，也没有检查本机运行环境。

### 本地工单筛选流程与边界

本功能仅在本机处理用户指定的 UTF-8、逗号分隔 CSV。数据列为 ticket_ref、priority_code、state_code；priority_code 的合法值为 H、M、L，state_code 的合法值为 O、C，ticket_ref 必须非空且在全文件中唯一。

本地确定性执行逻辑承担解析、校验、筛选和输出；不需要在线模型参与业务判定。以上是设计约束，并非实现或运行验证结果。
