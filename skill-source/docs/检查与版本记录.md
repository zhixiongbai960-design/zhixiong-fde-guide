# 检查与版本记录

当前0.4.4候选状态见[v0.4.4验证记录](v0.4.4-validation.md)。本文件保留0.4.0历史检查；当前专家包命名与分发见[v0.4.3验证记录](v0.4.3-validation.md)，方法基线的增量说明见[v0.4.2验证记录](v0.4.2-validation.md)。不要把旧轮次和旧测试数量当成本次结果。

版本0.4.0。此记录区分方法响应、代码测试、包装检查与宿主/真实业务验证。后两者不能由前者替代。本轮没有安装到WorkBuddy或操作客户系统。

## 第一轮：独立方法、来源和包装

检查18个独立入口、方法与模板、依赖闭包、33篇指南原文来源及许可。发现的许可相对路径错误已修正；生成包的正文逐字来自权威源。每个模块保留第一轮实际情境回复。部分初轮由同一上下文分组完成，不能当成完全隔离宿主测试。

仍遗漏：格式和闭包不证明真实回答正确，必须对好坏输入、范围冲突和缺证据进行行为验证。

## 第二轮：隔离回答与独立评审

重新仅提供各自独立包进行情境答复，检查需求完整/不完整/冲突、设计文档好坏、聊天原话与推测、POC探索、报价收尾、只读权限、维护及教学。

发现并修正：
- 案例教学不再默认第4–6天，按真实三天/七天/未定课表处理，不代称Datawhale认可。
- 工程检查曾把指南新建/更新示例变成未知项目的测试要求。修正后只按已确认操作，额外隔离测试覆盖只读与未知范围。
- 业务Skill构建示例曾在失败分支丢掉正文承诺的关联字段。强化成功/失败逐字段契约与测试；原10项测试虽通过，但没有覆盖此缺陷，不能用绿灯抹去问题。修正后13项生成代码合成测试通过，覆盖失败字段与不回显坏输入。

仍遗漏：单个模块通过不能证明总入口选对方法及跨阶段不丢状态，必须组装后另测。

## 第三轮：总入口组合与再审查

首次总包只在18模块各两轮有效记录及独立评审通过后组装。总包仅为固定快照，不调用远程小技能；所有方法、模板与33篇文字内置，按问题加载。

总包独立审查又发现协作授权方法有同类默认CRUD/经理角色问题，已修改权威方法，仅team模块哈希失效；新的两轮独立测试与独立复核已完成，随后重建总包并通过指纹校验。旧快照的陈旧QA确实被构建器拒绝，未绕过门禁。

首组组合情境：课堂需求→准入→规格→坏设计评审→修订复审；客户聊天更新→有限POC→收款后移交准备；离线原文定位→项目窗口→三天课程组织。客户/POC与指南/优先级情境已独立审查通过。第一组课堂题面一次给出全部后续内容，首轮提前使用后轮列名，不能算干净顺序测试；保留该记录，改为每次只发送当前轮的真实顺序测试。新的真实逐轮5次对话已独立审查通过：不提前补造列名、用新确认字段出规格、拒绝冲突设计、修订后允许限定实现、新客户未知权限不沿用旧范围。培训接管专项也已独立通过：不把演示或听懂当独立接管，给任务式训练、授权身份、续费和规则维护责任清单。最终本地结论为有限范围通过，完整依据见qa/evidence/total-final-review.md。

## 构建与低耦合验证

20项标准库打包测试覆盖缺依赖/循环/路径穿越/符号链接、旧产物保留、篡改、回滚、证据过期、确定性与影响范围。缺qa/modules.json时实际拒绝总包构建。只改need影响need/review/scope；改case、code、build、team分别只影响各自，不因无关导航或全局版本变化让全部小模块失效。共享工具/许可变化仍需重查相关全部模块。

## 发布边界

本报告记录发布前验证，不冒充远端发布证明。实际发布另核对远端提交、全部变更字节、旧入口及原指南未改，结果以GitHub提交和发布清单记录为准。保留失败历史，不把本地通过、GitHub发布、用户安装、真实业务验收混成一个状态。
